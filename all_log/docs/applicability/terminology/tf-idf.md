# tf-idf — 자연어 검색의 기본 점수

현행 rango 가 premise 를 고를 때 쓰는 방법이다. 우리 방법의 **비교 대상**이기도 하다.

---

## 1. 두 조각

```
   tf-idf(단어 w, 문서 d) =  tf(w, d)  ×  idf(w)
                              ▲            ▲
                    "이 문서에 많이 나오나"  "아무 데나 나오는 흔한 말인가"
```

- **tf** (term frequency) — 그 문서 안에서 그 단어가 얼마나 자주 나오나. **많을수록 ↑**
- **idf** (inverse document frequency) — 그 단어가 몇 개 문서에 나오나. **드물수록 ↑**

곱하는 이유: 둘 중 하나만 쓰면 망가진다.

| 쓰는 것 | 망가지는 방식 |
|---|---|
| tf 만 | `그리고`·`이다`·`the` 가 1등이 된다 (어디에나 많다) |
| idf 만 | 딱 한 문서에 한 번 나온 오타가 1등이 된다 |

---

## 2. 손으로 계산해 보기

문서 4개짜리 뭉치:

```
 d1 :  고양이 가 생선 을 먹었다
 d2 :  고양이 가 고양이 를 보았다
 d3 :  개   가 생선 을 먹었다
 d4 :  개   가 뼈   를 먹었다
```

### idf 부터 (문서 수 N = 4)

```
        단어      나오는 문서 수 df    idf = log(N/df)
      ─────────  ─────────────────  ─────────────────
        가            4               log(4/4) = 0.00   ← 아무 정보 없음
        먹었다        3               log(4/3) = 0.29
        고양이        2               log(4/2) = 0.69
        생선          2               log(4/2) = 0.69
        개            2               log(4/2) = 0.69
        뼈            1               log(4/1) = 1.39   ← 가장 강한 신호
```

```
   idf
   1.4 ┤ 뼈       █
   1.0 ┤
   0.7 ┤ 고양이/생선/개  ███
   0.3 ┤ 먹었다   ██
   0.0 ┤ 가       ·                ← df=N 이면 idf=0. 곱하면 사라진다
       └──────────────────────────
```

### 질의 `고양이 생선` 으로 점수 매기기

```
 문서   고양이 tf   생선 tf     점수 = Σ tf·idf
 ────  ──────────  ────────   ─────────────────────────────
 d1        1          1        1×0.69 + 1×0.69 = 1.38   ★ 1등
 d2        2          0        2×0.69 + 0      = 1.38   ★ 공동 1등
 d3        0          1        0      + 1×0.69 = 0.69
 d4        0          0        0                = 0.00
```

`d2` 는 `고양이` 를 두 번 써서 `d1` 을 따라잡았다. 실제로는 tf 에 `log(1+tf)`
같은 포화 함수를 씌워 이 효과를 눌러 준다(BM25 가 하는 일).

## 3. 우리 문제로 옮기면

```
   자연어 검색            premise 선택
   ──────────────    ─────────────────────────
   질의 (query)   →   현재 goal 의 텍스트
   문서 (doc)     →   lemma 하나의 진술문
   단어 (term)    →   식별자 토큰 (PTree, get, set, positive …)
```

```coq
goal   : PTree.get i (PTree.set j x m) = PTree.get i m
         └ 토큰: PTree get i set j x m ┘

lemma  : PTree.gso : … PTree.get i (PTree.set j x m) = PTree.get i m
         └ 토큰이 거의 그대로 겹친다 → 점수 높음 ✓
```

여기까지는 잘 된다. **문제는 겹치는 토큰이 없을 때**다.

## 4. 어디서 무너지나 — 실측 셋

### ① `unfold` 은 아예 못 찾는다

```coq
goal    : … Ple (dpc ctx) (st_nextnode s) …
gold    : unfold Ple
```

`Ple` 은 goal 에 **이미 있는** 상수다. 사전에서 "그 상수의 정의" 를 꺼내야 하는데
tf-idf 는 goal 과 겹치는 lemma 를 찾는 도구지, **goal 안의 상수를 펼칠 대상으로
지목하는 도구가 아니다.**

```
                       현행 tf-idf     우리 필터
   unfold gold 풀에       1.5%          100.0%
   unfold gold @10        0.0%           31.8%
   프롬프트 포함률       47.1%           83.3%
```

### ② 흔한 lemma 를 못 누른다

```
   f_equal : ?f ?x = ?f ?y
```

토큰이 `f`·`x`·`y` 뿐이라 어휘로는 아무 goal 과도 안 겹친다 →
tf-idf 는 낮게 준다. 그런데 실제로는 **거의 모든 goal 에 적용된다.**
어휘 idf 와 **실제 적용 빈도**가 어긋나는 것이다. → [idf.md](idf.md)

### ③ 이름이 다르면 끝이다

```coq
goal  : … Z.le a b …
gold  : Zle_bool_imp_le
```

`Z.le` 와 `Zle_bool` 은 문자열로는 겹치지만 `imp_le` 는 안 겹친다.
반대로 `plus_n_O` 처럼 이름과 진술문이 따로 노는 것도 많다.
**의미가 맞는지는 어휘가 판단할 수 없다.**

## 5. 실측 비교 (r10 · 312지점 · 순위만)

| 랭커 | @10 | @100 | 순위중앙 |
|---|---|---|---|
| 현행 tf-idf | 32.7% | 43.2% | 2 |
| 무작위 (필터 후) | 20.2% | 27.9% | 225 |
| applic-idf 단독 | 48.1% | 67.3% | 7 |
| **나이브베이즈** | **76.6%** | **87.5%** | **1** |

핵심 차이는 랭커가 아니라 **모수집단**이다. tf-idf 는 20,456개 전부를 상대로
어휘를 재고, 우리는 **Coq 이 적용 가능하다고 인정한 596개** 안에서 재기 시작한다.

## 6. 버리는 게 아니다

어휘 겹침은 여전히 **강한 신호**다. 나이브 베이즈가 학습한 가중치를 보면:

```
('nov', 3)   +8.19 bit    이름 어휘 겹침
('lex', 5)   +6.94 bit    진술문 어휘 겹침
```

`nov`/`lex` 는 tf-idf 가 세던 것과 같은 것이다. 다만 **하나의 신호로** 들어가고
다른 신호(적용가능성·evar 수·LCP)와 **비트 단위로 경쟁**한다. → [naive-bayes.md](naive-bayes.md)
