# applic-idf — 적용가능성 위에서 다시 정의한 idf

```
   applic-idf(L) = −log₂ P( L 이 필터를 통과함 )
```

> 자연어의 **원래 idf** 와 공식이 같고 **세는 대상만 다르다.**
> 원래 쪽은 [idf.md](idf.md) 에 있다.
>
> | | 세는 것 | 누가 판정 |
> |---|---|---|
> | idf | 단어가 든 **문서 수** | 문자열 일치 |
> | **applic-idf** | lemma 가 통과한 **goal 수** | **Coq 커널** (`w_unify`) |

---

## 0. 개괄 — 이 숫자를 어떻게 읽나

### 한 줄

```
   idf = "이걸 봐서 후보를 몇 번 반으로 접었나"
```

`1 비트 = 절반`. `3 비트 = 1/8`. `7 비트 = 1/128`. 그게 전부다.

### 실제로 나오는 범위 (r10 · 315지점 · 후보 10,508종)

```
   0 bit                                                      9.30 bit
   ├─────┬───────┬──────────┬─────────────┬────────┬──────────┤
   0     1       2          3.28          4.91     6.50    7.72 │
   │     │       │           │             │        │       │   └ 이론 상한
  전부  절반    1/4         1/10          1/30     1/100   1/300
  통과                                                      │
   ▲                                                        ▲
 소음                                                    사실상 최대

  실측:  최소 0.016   중앙 5.40   평균 5.01   최대 7.72
```

| 통과율 | 비트 | 뜻 | 어떤 것들 |
|---|---|---|---|
| 100% | 0.00 | 정보 없음 | — |
| 99% | **0.02** | 사실상 소음 | `Vector.nth` `Nat.iter` `VarMap.find` `Ring_polynom.*` |
| 81% | 0.30 | 거의 소음 | 보편 lemma 대부분 |
| **50%** | **1.00** | **후보를 딱 절반으로** | ← 기준점 |
| 33% | 1.61 | 약한 신호 | |
| 10% | 3.28 | 쓸 만함 | |
| 3.2% | 4.91 | 강함 | `Z.le_add_le_sub_r` |
| 1.0% | 6.50 | 매우 강함 | `sep_swap23`(1.3%, 6.13) |
| 0.3% | **7.72** | **포화 — 여기서 멈춘다** | 후보의 18.3% |

### 눈금이 세 개면 충분하다

```
     0 ~ 1 bit      "아무 데나 맞는다"   → 버려도 되는 신호
     1 ~ 4 bit      "좀 드물다"          → 다른 신호와 겹쳐 보면 쓸모
     4 bit 이상     "이 goal 전용에 가깝다" → 강하게 밀어도 된다
```

### ★ 절대값이 아니다 — 표본 수에 매인다

```
   상한 = log₂(n+1)          n = 잰 지점 수

     n = 100 지점  →  상한 6.66 bit
     n = 315 지점  →  상한 9.30 bit      ← 지금
     n = 1000 지점 →  상한 10.97 bit
```

**같은 lemma 라도 지점을 더 재면 비트가 커진다.** 그래서 서로 다른 실험의
IDF 값을 직접 비교하면 안 된다. 비교하려면 `비트 / log₂(n+1)` 로 정규화하거나
통과율(%)로 되돌려서 봐야 한다.

### ★ 위쪽이 포화한다 — 알려진 한계

```
   통과 1회  →  7.72 bit  ┐
   통과 1회  →  7.72 bit  ├─ 1,924종(18.3%)이 전부 같은 값
   통과 1회  →  7.72 bit  ┘
                            ▲ IDF 만으로는 이 안을 못 가른다
```

315지점으로는 "1회 통과" 보다 더 드문 것을 구분할 해상도가 없다.
그래서 applic-idf 단독은 @10 **48.1%** 에서 멈추고, 나머지는 다른 신호(구조·어휘·evar)가
갈라야 한다. → [naive-bayes.md](naive-bayes.md)

### 왜 라플라스 보정이 필요한가

```
   보정 없이:  −log₂(0/315) = ∞          ← 한 번도 안 통과 = 무한대
   보정하면:  −log₂(0.5/316) = 9.30      ← 유한한 값

   idf = −ln( (통과횟수 + 0.5) / (지점수 + 1) )
                        ▲              ▲
                    분자에 0.5      분모에 1
```

드문 것을 과대평가하지 않으려는 것이다. 표본 315개로 "0%" 라고 단정할 수 없다 —
316번째 지점에서 통과할 수도 있다.

## 1. 어떻게 세나

```
   I(L) = −log₂ P( L 이 필터를 통과함 )
                    ▲
             goal 여러 개에 실제로 필터를 돌려 센 비율
```

형태는 똑같다. **재는 대상만 어휘 → 적용가능성으로 바꿨다.**

```
   P(통과)   1.0     0.5     0.25    0.125    0.06    0.03
   비트       0       1       2       3        4       5
             │       │       │       │        │       │
   f_equal ──┘       │       │       │        │       │   0.0 bit
   eq_sym ───────────┘       │       │        │       │
   snd, projT1 ──────────────┘       │        │       │
   Z.add_comm ───────────────────────┘        │       │
   PTree.gso ─────────────────────────────────┴───────┘   6.3 bit
```

### 실측 — "어디에나 맞는 것" 이 정말 있다

```
   191개 lemma 가 지점의 90% 이상에서 살아남는다.
   지점당 후보의 16.2% 를 차지한다 (84,403/521,869).

   snd · projT1 · uncurry · eq_stepl · f_equal · eq_ind · proj1 …
```

이것들은 **필터를 통과해도 정보가 없다.** 필터만으로는 못 지우고
랭커가 눌러야 한다. 이게 applic-idf 가 하는 일이다.

## 2. 원래 idf 와 나란히 놓고 보기

| | 원래 idf | applic-idf |
|---|---|---|
| 세는 것 | 단어가 든 **문서 수** | lemma 가 통과한 **goal 수** |
| 누가 세나 | 문자열 일치 | **Coq 커널** (`w_unify`) |
| 비용 | 뭉치 한 번 훑기 | goal 표본마다 필터 1회 |
| 놓치는 것 | 이름이 다르면 끝 | 없음 (의미로 잰다) |
| 잡음원 | 불용어 | 어디에나 맞는 lemma |

### 실측 효과 (r10 · 312지점 · 순위만)

| 랭커 | @10 | @100 | 순위중앙 |
|---|---|---|---|
| 무작위 (필터 후) | 20.2% | 27.9% | 225 |
| **applic-idf 단독** | **48.1%** | **67.3%** | **7** |
| 비트합 (idf+lcp+lgg−e) | 53.2% | 72.1% | 5 |
| 나이브베이즈 (전 신호) | 76.6% | 87.5% | 1 |

**신호 하나로 20.2% → 48.1%.** 다른 단일 신호(lgg 36.5% · lcp 36.9% · evar 24.7%)를
크게 앞선다. 그다음은 신호를 합치는 방법이 올린다.

## 3. 한계

- 표본으로 추정한다. 드문 lemma 는 `P` 추정이 불안하다 → 평활(smoothing) 필요.
- 프로젝트가 바뀌면 분포가 바뀐다. CompCert 에서 잰 IDF 를 mathcomp 에 그대로
  쓰면 안 맞는다. 프로젝트별로 다시 재는 게 맞다.
- `f_equal` 을 누르는 것이 **항상** 옳지는 않다. 진짜 `f_equal` 이 답인 지점도 있다.
  그래서 IDF 단독이 아니라 다른 신호와 **비트로 경쟁**시킨다. → [naive-bayes.md](naive-bayes.md)

[[rig]] · [[structural-idf]] 로 해결했다 — `Î(L)=rig·log₂b`, 말뭉치 불필요.
r11_v5 실측에서 경험적 idf 는 **넣으면 손해**, rig 는 −16.4pp 단독 최대 기여.
