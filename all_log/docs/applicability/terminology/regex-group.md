# 정규식 그룹 — 캡처 / 비캡처

> 이 문서가 여기 있는 이유: 이걸 몰라서 **평가가 두 번 조용히 죽었다.** §5 참조.

---

## 0. 한 줄

```
   (…)     캡처 그룹      묶고 + 값을 꺼낸다      → groups() 에 들어간다
   (?:…)   비캡처 그룹    묶기만 한다             → groups() 에 안 들어간다
```

`?:` 를 붙이면 **번호를 안 먹는다.**

---

## 1. 왜 묶나 — 두 가지 목적이 섞여 있다

```python
r"(ab)+"        # ① 반복을 걸려고 묶는다      — 값은 필요 없다
r"ver=(\S+)"    # ② 값을 꺼내려고 묶는다      — 값이 필요하다
```

정규식은 이 둘에 **같은 문법 `(…)`** 을 쓴다. 그래서 ①만 하려는데
번호가 하나 밀리는 사고가 난다.

```
   패턴:  (ab)+(\d+)
                ▲    ▲
             그룹1  그룹2      ← "숫자를 꺼내려면 group(2)"  … 헷갈린다

   패턴:  (?:ab)+(\d+)
                   ▲
                그룹1         ← 이제 group(1) 이 숫자다
```

---

## 2. 실제 동작

```python
import re
S = "ver=r10 PTree.gso ap=1"

re.search(r"ver=(\S+)\s+(\S+)\s+ap=(\d)", S).groups()
# → ('r10', 'PTree.gso', '1')          그룹 3개

re.search(r"ver=\S+\s+(\S+)\s+ap=(\d)", S).groups()
# → ('PTree.gso', '1')                 그룹 2개  ← ver 를 아예 안 묶음

re.search(r"ver=(?:\S+)\s+(\S+)\s+ap=(\d)", S).groups()
# → ('PTree.gso', '1')                 그룹 2개  ← 묶되 안 세는 것
```

```
                 묶나?   번호를 먹나?   |·, +, ? 를 걸 수 있나?
   ─────────  ──────  ───────────  ────────────────────
   (…)          O          O                O
   (?:…)        O          X                O
   (없음)        X          X                X
```

**`\S+` 처럼 하나짜리면 괄호가 아예 필요 없다.** `(?:…)` 는
`(?:ab|cd)+` 처럼 **여러 조각에 반복·선택을 걸어야 할 때** 쓴다.

---

## 3. 자주 쓰는 다른 `(?…)` 들

| 문법 | 이름 | 하는 일 |
|---|---|---|
| `(?:…)` | 비캡처 | 묶기만 |
| `(?P<이름>…)` | 이름 있는 캡처 | `m.group("이름")` 으로 꺼낸다 |
| `(?=…)` | 전방 탐색 | "뒤에 이게 오면" — **소비하지 않는다** |
| `(?!…)` | 부정 전방 탐색 | "뒤에 이게 안 오면" |
| `(?<=…)` | 후방 탐색 | "앞에 이게 있으면" |
| `(?i)` | 플래그 | 대소문자 무시 |

```
   r"foo(?=bar)"     foobar 의 foo 만 잡는다 (bar 는 안 먹음)
   r"\bapply(?!_)"   apply 는 잡고 apply_thm 은 안 잡는다
```

**전방·후방 탐색도 번호를 안 먹는다.**

---

## 4. 이름 있는 그룹이 더 낫다

번호는 패턴을 고칠 때마다 밀린다. 이름은 안 밀린다.

```python
W = re.compile(r"CHECK\s+ver=(?P<ver>\S+)\s+(?P<name>\S+)\s+ap=(?P<ap>\d)")
m = W.search(line)
m.group("name")          # 앞에 그룹을 몇 개 더 넣어도 안 깨진다
m.groupdict()            # {'ver': 'r10', 'name': 'PTree.gso', 'ap': '1'}
```

우리 스크립트들은 `g[0]`, `g[16]` 처럼 **번호**로 쓰고 있다.
이름으로 바꾸면 §5 의 사고가 구조적으로 안 난다.

## 5. ★ 우리가 실제로 당한 것

플러그인이 r9 → r10 으로 가면서 출력에 `ver=` 필드가 붙었다.
정규식에 `ver=(\S+)` 를 **캡처로** 추가했는데, 뒤의 인덱스는 그대로 뒀다.

```
   전     CHECK PTree.gso ap=1 …            그룹 17개,  g[0] = 이름
   후     CHECK ver=r10 PTree.gso ap=1 …    그룹 18개,  g[0] = 'r10'  ← 전부 한 칸 밀렸다
                ▲ 캡처로 추가
```

```python
g = m.groups()
assert len(g) == 17, g       # ← 여기서 터졌다
recs.append({"name": g[0],   # ← 안 터졌으면 name 에 'r10' 이 들어갔을 것
             "ap": int(g[1]), …})
```

**고친 방법 — 한 글자:**

```python
r"CHECK\s+ver=(\S+)\s+(\S+)\s+ap=..."     # 18 그룹
r"CHECK\s+ver=\S+\s+(\S+)\s+ap=..."       # 17 그룹 ← 캡처를 뺐다
```

`ver` 값은 안 쓰므로 캡처할 이유가 없었다. 인덱스를 전부 밀 필요도 없다.

### 왜 이게 위험했나

```
   ┌ assert 가 없었다면 ───────────────────────────────────┐
   │  name  = 'r10'          (모든 지점에서 같은 값)        │
   │  ap    = int('PTree.gso') → ValueError                │
   │        → 바깥 except 가 삼킴 → recs = []               │
   │        → 지점 0 → "성능이 0%" 로 보인다               │
   └──────────────────────────────────────────────────────┘
```

**틀린 답이 아니라 조용한 0** 이 나온다. 이 세션에서 같은 종류로 세 번 당했다:

| | 원인 | 증상 |
|---|---|---|
| ① | OCaml 문자열 줄바꿈이 공백을 남겨 `\s+` 가 아닌 단일 공백 패턴이 안 맞음 | 전 지점 0 |
| ② | `capture_output` 을 `Popen` 에 넘겨 `TypeError` → 바깥 `except` 가 삼킴 | 전 지점 0 |
| ③ | `ver=` 캡처 추가로 그룹이 17→18 | 전 지점 0 |

### 대책 — 시동 자가검사

그래서 스크립트마다 **실제 출력 표본**으로 정규식을 시동 시에 검사한다.

```python
_SAMPLE_CHECK = ("CHECK ver=r10 PTree.gso ap=1 in=1 rw=1 dnA=1 dnR=1 indexed=1 "
                 "sides=0 headm=1 unifm=1 nap=349 nin=456 nrw=268 redex=20 "
                 "raw=34461 keypass=5821 sec=0.534")
assert WHY.search(_SAMPLE_CHECK), "CHECK 정규식이 실제 출력과 어긋난다"
```

그리고 **조기 중단**:

```python
if n >= 19 and not _first_ok:
    print("■ 20개 연속 지점 0 — 원인 분포:", dict(BLOCK))
    raise AssertionError("배선을 확인하라")
```

이 두 개가 세 번째 사고를 **9분 만에** 잡았다.

---

## 6. 규칙

```
   ① 값이 필요 없으면 괄호를 아예 쓰지 않는다
   ② 묶기만 필요하면 (?:…)
   ③ 값이 필요하면 (?P<이름>…) — 번호 대신 이름
   ④ 필드를 추가하면 표본 문자열로 자가검사를 갱신한다
```
