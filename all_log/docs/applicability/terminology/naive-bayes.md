# 나이브 베이즈 — 신호 합치기

> 목적: 필터를 통과한 수백 개 후보를 **줄 세우는 것.**
> 이 문서는 `f`·`gold`·입력·출력을 하나씩 정의한다.

---

## 0. 한눈에

```
   입력                                     출력
  ─────────────────────────────────    ────────────────────────
   지점 하나 (goal + 가설)                후보마다 실수 하나 (단위: 비트)
   + 필터가 통과시킨 후보 목록 C          → 그 값으로 내림차순 정렬
   + 후보마다 신호 (lcp, lgg, e, …)
   + 학습된 가중치표 W
```

```
   score : (후보) → ℝ          큰 값이 위.  값 자체가 아니라 **순서**만 쓴다.
```

---

## 1. `gold` — 정답 premise

```
   증명의 한 스텝:     rewrite PTree.gso.
                              └────┬────┘
                                 gold
```

- **정의**: 그 지점에서 **사람이 실제로 쓴** 외부 lemma 이름.
- 어떻게 얻나: CoqStoq 의 원본 증명에서 정규식으로 뽑는다
  (`apply|eapply|rewrite|erewrite|unfold|destruct|induction|case|elim|exact` 다음 이름).
- 학습의 **정답 표지(label)** 다. 각 지점에 **정확히 하나**.
- 지역 가설(`H`, `IHl`)을 쓴 스텝은 **뺀다** — 검색 대상이 아니다(`r["local"]`).

```
   지점 하나에서
      후보 C = { L₁, L₂, …, L₈₈₂ }        ← 필터가 통과시킨 것
      그중 gold = sep_swap23              ← 양성 1개
      나머지 881개                        ← 음성
```

**양성:음성 = 1:수백.** 극단적 불균형이고, 이게 뒤의 사전확률 항으로 나온다.

## 2. `f` — 특징 하나

`f` 는 단어도 아니고 숫자도 아니다. **`(이름, 구간)` 짝**이다.

```
   ('lcp', 3)      "lcp/|goal| 가 3번 구간(0.3~0.5)에 든다"
   ('ch', 'rw')    "이 후보는 rewrite 채널에서 나왔다"
   ('std', 1)      "stdlib 소속이다"
```

### 후보 하나 = 특징 **정확히 12개**

고정 길이 벡터다. 가변 길이 bag-of-words 가 아니다.

```
   PTree.gso  →  [ ('lcp',1) ('lgg',3) ('e',2)  ('z',3)
                   ('nm',0)  ('ing',1) ('occ',0) ('idf',3)
                   ('ch','rw') ('lex',2) ('nov',0) ('std',0) ]
```

| 이름 | 원래 값 | 뜻 |
|---|---|---|
| `lcp` | `lcp/|goal|` | 트라이에서 같이 내려온 깊이 (정규화) |
| `lgg` | `lgg/|goal|` | 공통 뼈대 크기 (정규화) |
| `e` | evar 개수 | 아직 안 정해진 자리. **작을수록 좋다** |
| `z` | `z/|goal|` | redex 크기 |
| `nm` | 매칭 수 | 몇 군데서 맞았나 |
| `ing` | 0/1 | redex 가 goal 안인가 (가설 안이 아니라) |
| `occ` | 출현 횟수 | unfold 용 — 그 상수가 goal 에 몇 번 나오나 |
| `idf` | applic-idf | 이 lemma 가 얼마나 드문가 |
| `ch` | 문자열 | 어느 채널에서 나왔나 (`ap`/`in`/`rw`/`uf`/`ds`/`dc`) |
| `lex` | 어휘 겹침 | goal 과 진술문 토큰이 얼마나 겹치나 |
| `nov` | 이름 겹침 | `repr_canonical` ↔ goal 의 `repr_*` |
| `std` | 0/1 | stdlib 인가 |

### 연속값은 구간으로 자른다

```python
out.append(("lcp", _bucket(s["lcp"] / g, (0.05, 0.15, 0.3, 0.5, 0.75))))

   lcp/g   0 ── 0.05 ── 0.15 ── 0.3 ── 0.5 ── 0.75 ── 1
   구간      0      1       2      3      4      5
```

**왜 자르나**: 구간마다 가중치를 따로 배우므로 **단조를 가정하지 않는다.**
비트합은 "클수록 좋다" 를 강제했지만, 여기선 `('lcp',4)` 가 `('lcp',5)` 보다
가중치가 클 수도 있다 — 데이터가 그렇게 말하면.

**대가**: 경계값(0.05, 0.15, …)은 **손으로 정했다.** 남은 임의값이다.

## 3. `W` — 가중치표 (학습 대상)

```
   w(f) = log₂  P(f | gold)          f 를 가진 비율,  gold 인 후보들 중에서
                ──────────
                P(f | ¬gold)         f 를 가진 비율,  gold 아닌 후보들 중에서
```

```
   P(f|gold) > P(f|¬gold)   →  비율 > 1  →  w > 0   ★ 가점
   P(f|gold) = P(f|¬gold)   →  비율 = 1  →  w = 0     무의미한 특징
   P(f|gold) < P(f|¬gold)   →  비율 < 1  →  w < 0   ✗ 감점
```

**감점이 공짜로 나온다.** 비트합(`−log P`)은 항상 양수라 이걸 표현할 수 없었다.

### 어떻게 세나

```python
for r in rows:                     # 지점마다
    for x in cand:                 # 필터를 통과한 후보마다
        fs = feats(x, …)           # 12개
        if x == gold: npos += 1; [pos[kv] += 1 for kv in fs]
        else:         nneg += 1; [neg[kv] += 1 for kv in fs]

for kv in keys:
    p = (pos[kv] + 1.0) / (npos + 2.0)      # 라플라스 보정
    q = (neg[kv] + 1.0) / (nneg + 2.0)
    W[kv] = log2(p / q)
```

```
   450지점 × 후보 수백
        │
        ├─ gold 인 것    npos ≈ 315개      → pos 카운터
        └─ 아닌 것       nneg ≈ 수십만개   → neg 카운터
        │
        └─▶ 특징 종류마다 log₂(p/q) 하나 = W
```

**W 는 지점과 무관한 전역 표**다. 한 번 학습하면 모든 지점에 쓴다.

### 라플라스 보정이 왜 필요한가

```
   보정 없이:  pos[('e',0)] = 0 이면  log₂(0/q) = −∞     ← 한 표본이 후보를 영구히 죽인다
   보정하면:  (0+1)/(npos+2) 로 바닥이 생긴다
```

315개 양성으로 12종류 × 여러 구간을 추정한다. **양성 표본이 적어서** 보정이 없으면
0 칸이 잔뜩 생긴다.

## 4. `score` — 출력

```
   score(L) = Σ  w(f)          f 는 L 의 12개 특징
             f∈feats(L)
```

```
   PTree.gso 의 12개 특징            W 에서 찾은 가중치
  ─────────────────────────      ────────────────────
   ('e', 0)                            +12.32
   ('nov', 3)                           +8.19
   ('lex', 5)                           +6.94
   ('idf', 4)                           +5.20
   ('lgg', 5)                           +4.79
   …
   ('std', 1)                           −2.33
   ('ch', 'in')                         −2.41
                                      ────────
   score                               = 35.10 bit
```

### 이 숫자가 뜻하는 것 — 유도

베이즈 정리를 **승산비(odds)** 로 쓰면:

```
   P(gold | f₁…f₁₂)      P(gold)        P(f₁|gold)        P(f₁₂|gold)
   ───────────────  =  ─────────  ×  ───────────  × … × ────────────
   P(¬gold| f₁…f₁₂)     P(¬gold)      P(f₁|¬gold)       P(f₁₂|¬gold)
                            ▲                    ▲
                        사전 승산            각 특징의 증거
```

양변에 `log₂` 를 씌우면 곱이 합이 된다:

```
   log₂(사후 승산)  =  log₂(사전 승산)  +  Σ w(fᵢ)
                                            └──┬──┘
                                            = score(L)
```

```
   ★ score(L) = "이 후보의 특징들이 gold 이라는 쪽으로 몇 비트어치 증거를 주나"
                 사전확률을 뺀 **증거의 양**이다.
```

### 왜 정렬에 그대로 써도 되나

사전 승산 `P(gold)/P(¬gold)` 는 **한 지점 안에서 모든 후보에게 똑같다**
(후보 882개 중 1개가 gold → 1/881, 후보에 안 매인다). 따라서

```
   사후확률 순서  =  score 순서
```

상수를 더한 것뿐이라 **순위가 안 바뀐다.** 그래서 score 만 계산하면 된다.

### 단위 읽는 법

```
   score = +10 bit   →  이 특징들을 보고 나서 승산이 2¹⁰ = 1,024배 올랐다
   score =   0 bit   →  아무 증거 없음 (사전확률 그대로)
   score = −5 bit    →  오히려 32배 내려갔다
```

### ⚠ 확률이 아니다

`score` 는 0~1 이 아니고 정규화도 안 돼 있다. **순위에만 쓴다.**
확률이 필요하면 사전 승산을 더하고 시그모이드를 씌워야 하는데, 우리는 안 쓴다.

## 5. 전체 흐름

```
  ┌─ 학습 (한 번) ──────────────────────────────────────────┐
  │  지점들 ──▶ 각 후보에 label(gold/¬gold) ──▶ 12특징 세기   │
  │                                     ──▶ W = log₂(p/q)   │
  └─────────────────────────────────────────────────────────┘
                            │ W
  ┌─ 추론 (지점마다) ────────▼───────────────────────────────┐
  │  goal ──▶ 필터 ──▶ 후보 C (882개)                        │
  │              각 L∈C:  feats(L) → 12개 → Σ W → score(L)   │
  │              정렬 ──▶ 상위 K 개를 프롬프트로               │
  └─────────────────────────────────────────────────────────┘
```

**교차검증**: 같은 지점으로 학습하고 평가하면 안 된다.
`train_nb(..., skip_idx=)` 로 평가할 정리를 빼고 학습한다 (5겹).

## 6. "나이브" 가 뜻하는 것

```
   P(f₁…f₁₂ | gold)  =  P(f₁|gold) × P(f₂|gold) × … × P(f₁₂|gold)
                                    ▲
                          특징끼리 독립이라고 가정
```

**우리 경우 이 가정은 틀렸다.** `lcp` 와 `lgg` 는 강하게 상관된다
(`PTree.gso` 는 `lgg=15, lcp=15`).

그래도 비트합보다 나은 이유:

```
   비트합       각 신호의 −log P 를 그냥 더한다.  겹치면 그대로 이중 계산
   나이브베이즈  겹치면 각각의 log(p/q) 가 자동으로 작아진다
                (둘 다 gold·¬gold 를 비슷하게 가르므로 판별력이 나뉜다)
                → 이중 계산을 **부분적으로** 흡수한다
```

완전한 해법은 상관을 모델링하는 것(로지스틱 회귀·트리 부스팅)이지만,
**해석 가능성**을 잃는다. 지금은 가중치표를 눈으로 읽을 수 있는 게 값이 크다.

### 최대엔트로피라는 것

각 특징의 주변 통계 `P(f|gold)`·`P(f|¬gold)` 만 알 때,
**그 통계와 모순되지 않으면서 가장 가정을 적게 하는** 분포가 정확히 이 형태다.

```
   손으로 고른 가중치   →  근거 없는 가정을 넣은 것 (2.0? 1.5? 왜?)
   나이브 베이즈        →  아는 것만 쓰고 나머지는 최대한 무지하게
```

## 8. 남은 약점

- 독립 가정 위반 (`lcp`·`lgg`).
- 구간 경계가 손으로 정한 값.
- 양성 표본이 지점당 1개뿐이라 `npos` 가 작다 (307). 특징 종류가 많아지면 과적합.
- 채널(`ch`)을 특징으로 넣었지만, 실제로는 **채널마다 다른 랭커**를 쓰는 게 맞을 수 있다.
