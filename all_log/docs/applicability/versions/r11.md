# r11 — 채널을 `ap · in · rw · rwh` 넷으로 좁힌다

> 이전: [r10](r10.md) · 결과: [../results/r11.md](../results/r11.md)

## 바꾼 것 — 다섯

### ① 채널 축소 — `uf`·`ds`·`dc` 를 뺀다

```ocaml
let wide_channels = ref false        (* 기본 꺼짐. ApplicWideChannels 1 로 되살림 *)
let out_uf = if not !wide_channels then [] else …
let out_ds = if not !wide_channels then [] else …
let dc_raw = if not !wide_channels then [] else …
```

**근거 — 채널 기여도 실측 (CompCert 315지점):**

| 채널 | gold 포함 | **단독 기여** | 후보 중앙 |
|---|---|---|---|
| ap | 115 | 46 | 334 |
| in | 70 | 9 | 618 |
| rw | 88 | 47 | 418 |
| **uf** | 109 | **75** | **7** |
| **ds** | 0 | **0** | 3 |
| **dc** | 36 | **0** | 171 |

> 단독 기여 = 그 채널을 빼면 gold 을 아예 못 찾게 되는 지점 수.

- **`ds` 는 죽어 있다.** 귀납형 **타입 이름**(`Z` 205 · `option` 117 · `list` 103…)을
  내는데 gold 은 **함수 이름**(`zle`·`peq`)이다. 315지점에서 gold 포함 **0회**.
- **`dc` 는 단독 기여 0.** 찾는 36개를 전부 다른 채널도 찾으면서 잡음 171개를 더한다.
- **`uf` 는 기여가 크지만 검색이 아니다.** 후보가 정의상 goal·가설에 이미 보이는
  이름이고(`terms = concl :: hyps` 를 훑는다), 모델은 증명 상태를 보고 있다.
  → [../concepts/unfold.md](../concepts/unfold.md) §4.5

### ② ssreflect 묶음 규칙 — 타입이 튜플인 것

```coq
Definition inE := (in_set, in_set1, inE).     (* finset.v:366 *)
Definition inE := (mem_seq1, in_cons, inE).   (* seq.v:1539 *)
```

타입이 등식이 아니라 `(P1 * P2 * P3)%type` 이라 R 색인에 못 들어갔다.
mathcomp 실패 gold 중 **`inE` 가 9건으로 최다**였다.

```ocaml
let rw_sides_all ?(evars = true) env sigma t =
  … | Ind prod when 인자 2개 -> 성분마다 재귀 (inside := true)
    … | Prod -> inside 면 벗긴다 (성분은 `forall x y, … = …` 꼴이라)
```

비용 **+0.2%** (raw 45,127 → 45,213). 잡힌다: `CHECK inE rw=1 dnR=1`.

### ③ 속도 — 머리가 맞는 깊이만 단일화

`suffix_compat` 이 "어느 한 깊이라도 맞나" 만 보고 통과시킨 뒤
`depth_of` 가 **깊이 0~20 을 전부 커널 단일화**했다.

```ocaml
let suffix_depths sigma ty concl = …   (* 맞는 깊이 목록을 돌려준다 *)
let want n = List.mem n ds             (* 그 깊이에서만 단일화 *)
```

같은 술어를 깊이별로 적용하는 것이라 **집합이 동일**하다.

```
전:  apply=349 applyin=456 rewrite=268 rewriteh=147  sec=0.45
후:  apply=349 applyin=456 rewrite=268 rewriteh=147  sec=0.39   (−14%, 수치 동일)
```

### ④ δ 전개 — 만들었지만 **기본 꺼짐**

mathcomp 은 등식을 정의 뒤에 숨긴다.

```coq
Lemma mulrA : forall [s : semiRingType], associative *%R.
Definition associative op := forall x y z, op x (op y z) = op (op x y) z.
```

`whd_all` 로 βδ 를 열면 잡힌다(`whd_delta` 는 β 를 안 해서 멈춘다).
그런데 비싸다:

```
ApplicDelta 0   raw 45,213 · nrw 406 ·  2.2초
ApplicDelta 1   raw 63,391 · nrw 635 · 45.6초   ← 22배
```

색인 **구축**까지 터진다 — mathcomp 은 후보 ~35,000개고 타입마다 `whd_all`
을 하면 정리당 25분+. VAL 150 · TEST 236 정리를 이 속도로는 못 돈다.
**mathcomp 은 VAL/TEST 의 각 ~20%, TRAIN 엔 0%** 라 값을 못 한다고 보고 껐다.

### ⑤ 메모리 봉쇄

CompCert `backend/Kildall.v` 의 `reachable_predecessors` **정리 하나**가
coqtop 을 112GB 까지 키웠다 (45정리 중 1건, 나머지는 정상).
수집 스크립트의 자식에 **12GB 상한**을 건다.

```python
def _memcap():
    resource.setrlimit(resource.RLIMIT_AS, (12 * 1024**3,) * 2)
Popen(..., start_new_session=True, preexec_fn=_memcap)
```

## 도중에 두 번 낸 같은 실수 — sigma 스레딩

`rw_sides_all` 이 `new_evar` 로 만든 sigma 를 안 돌려줘
`Anomaly "in retyping: Unknown evar"`. 그리고 **색인 단계에서는 evar 가
애초에 필요 없었다** — `constr_val_discr` 가 열린 `Rel` 을 와일드카드로
처리하므로 치환 없이 내려가면 된다. 안 그랬을 때 sigma 가 폭발해
coqtop 이 215GB 를 먹었다.

```ocaml
if evars then                        (* 검증: 실제 단일화 필요 *)
  let (s', ev) = Evarutil.new_evar env s a in
  go inside (d+1) s' (Vars.subst1 ev b)
else                                 (* 색인: 패턴만 뽑으면 된다 *)
  go inside (d+1) s b
```

→ [../terminology/sigma.md](../terminology/sigma.md)
