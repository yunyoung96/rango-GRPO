# r18 — RRF 동률 평균순위 (기계적 공정성 수리 · 학습 0)

## 무엇이 바뀌었나 — 한 줄

r17 의 RRF 가 쓰던 순위가 **동률을 자의로 펼치고 있었다**(argsort — 사실상
이름순). r18 은 동률에 **평균순위**를 준다. 수식·파라미터 변화 없음:

```
score_c(L) = 1/(20 + r̄_구조c(L)) + 1/(20 + r̄_어휘(L))     r̄ = 동률 평균순위
```

왜 중요한가: rwh 풀(~1.2k)은 같은 redex 를 문 후보들이 구조점수 **동률**로
뭉친다. 자의 배열은 그 뭉치 안에서 gold 를 임의 위치로 밀었다 — 융합 순위의
왜곡. 평균순위는 뭉치를 공정하게 한 자리에 둔다.

## 교훈

성능 개선이 새 신호·새 식이 아니라 **순위 산정의 공정성**에서 나왔다.
순위 기반 방법(RRF)을 쓸 때 동률 처리는 하이퍼파라미터가 아니라 정확성 문제다.

## 계보와 번호 규약
r17(채널별 RRF · k=20 · exact 편입) → **r18(+동률 평균순위)** ← 현재 최종

★ 번호는 두 계열이다:
- **플러그인 ver**(필터, STAT 의 `ver=`): 필터 이진이 바뀔 때만 증가 — 현재 **r15**
  (r13 iff→P · r14 cap28 · r15 관계δ 가 마지막 필터 변화)
- **방법 버전**(versions/rN.md): 랭커 포함 전체 — r16~r18 은 랭커 층만 바뀌어
  플러그인은 r15 그대로다. 즉 "r18 방법 = r15 필터 + r18 랭커".

## 실적용 감사 (2026-09-02 · assert_succeeds 지상진실 · VAL 12지점)

"복원 후보가 실제로 그 tactic 으로 적용되는가" — 채널 전원 + 비후보 표본에
tactic 을 실제 실행(assert_succeeds, 후보당 ~0.11ms)해 잰 정밀도.

검증 의미론을 필터와 맞추는 것이 관건이었다(불공정 3연발 수리):
① 지점 = 수집기와 동일한 이름-전술 스텝 (intros 전 상태 배제)
② `erewrite` (필터가 evar-허용 w_unify = erewrite 의미론이므로)
③ **양방향** `erewrite L | erewrite <- L` (필터는 양변 색인) + Setoid 로드

| 채널 | 후보수 | 정밀도 | 비후보 위음성률† |
|---|---|---|---|
| ap | 3,093 | **96.6%** | 10.6% |
| in | 2,825 | **99.8%** | 26.1%‡ |
| rw | 2,833 | 54.6% | 9.4% |
| rwh | 2,234 | **88.4%** | 15.3% |

† 비후보 = 합집합 내 타채널 이름(보수적 근사). ‡ in 의 위음성은 과대 —
`eapply L in H` 는 modus ponens 류가 아무 Prop 가설에나 성공할 만큼 관대해
"적용은 되나 유용성 낮은" 후보가 다수 (필터는 의도적으로 좁게 본다).

판독: **apply 계열 필터는 사실상 건전**. rw 54.6% 의 잔여 거짓양성은
binder 아래·의존 위치의 닫힌 부분항 — 단일화는 되지만 rewrite 가 원리적으로
못 닿는 위치로, 랭커가 부분 보상 중(rw @10 76.5). 방향 불공정만으로
rw 25.5→54.6 · rwh 40.6→88.4 가 뒤집힌 것은 "감사도 의미론을 맞춰야
한다"는 방법론 교훈.

다음 후보(r19?): rw 채널에 **커널 실검증 가지치기** — 후보당 0.11ms 이므로
rw 후보 ~300개 실검증은 +33ms/노드. 정밀도 54.6→~100% 로 풀이 절반으로
줄어 랭킹도 이득 가능. 속도예산(217+33 < 300ms) 안.
