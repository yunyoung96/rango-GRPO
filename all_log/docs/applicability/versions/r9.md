# r9 — decide 채널 조임 · `check_tac` 도 지역이름 출력

> r7 에서 넓힌 `decide` 채널이 **역효과**를 냈다.

## 왜

r7→r8 사이에 `decide` 를 `sumbool`/`bool` 에서 **모든 귀납형 결론**으로 넓혔다
(`destruct (Lex 3)` 같은 형태를 잡으려고). 채널이 107 → **490** 으로 불었는데
통과 조건이 *"결론 인자의 머리가 goal 에 나타나면"* 이라 너무 헐거웠다.

실측 — 후보만 늘고 신호가 못 갈랐다:

| tactic | @10 (r8) | @10 (넓힌 뒤) |
|---|---|---|
| destruct | 52.0% | **46.0%** ↓ |
| case | 63.6% | **54.5%** ↓ |

## 바꾼 것

```ocaml
(* 머리 일치가 아니라 실제 커널 단일화를 요구한다 *)
Array.iter (fun x ->
    if rigid_head sigma x then
      List.iter (fun st ->
          if same_head sigma x st && unify1 env sigma x st then ok := true)
        gsubs) args
```

`destruct (peq r1 r2)` 는 `r1`·`r2` 가 **goal 에 실제로 있어야** 뜻이 있다.

- **`check_tac` 도 `HYPS`/`GBIND` 를 출력**하게 했다. `filter_tac` 에만 있어서
  `applic_check` 를 쓰는 다중프로젝트 측정이 `destruct l` 의 `l` 을 전부 미검출로 셌다
  (VAL 1차 58.6% 의 상당 부분).
- **판본 표시**: `retrieval_version = "r9"` 를 모든 출력에 찍는다.
