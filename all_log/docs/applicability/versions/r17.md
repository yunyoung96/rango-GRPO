# r17 — 최종: 채널별 RRF (k=20 · 학습 0)

## 최종 알고리즘

```
score_c(L) = 1/(20 + r_구조c(L)) + 1/(20 + r_어휘(L))      채널 c 공통 골격

  r_구조c : 채널별 구조 점수로 줄 세운 등수 (가중치 없음)
              ap · in · rwh :  share + overlap + rig      (S1)
              rw            :  share + rig                (S2 — overlap 제외)
  r_어휘  : tf-idf 코사인(goal ↔ 진술문) 등수
  계열    : exact·eexact 는 apply 계열 (결론 완전일치 = apply 특수형)
  그외    : rango tf-idf (§4 지침)
```

## 신호 정의 — share · overlap · rig

세 신호 모두 "후보 lemma L 을 goal(또는 가설) t 에 맞춰본 결과"에서 나온다:

```
share   = |매칭된 부분구조| / |t|         "t 를 얼마나 설명하나" (포섭 격자의 meet 크기)
          ap·in : lgg = 결론(전제)과 t 의 최소일반화 공통 구조 크기 — 정밀
          rw·rwh: z   = 등식 패턴이 삼킨 redex 의 크기 — 근사(부분항 단위)
          예: goal `S n ≤ m`, 후보 결론 `S ?a ≤ ?b` → 구조 전부 공유 → share ≈ 1

overlap = |lcp| / |t|                    판별트리 전위순회 라벨열의 최장 공통 접두사
          share 의 "공짜 근사" — 트리가 조회 중에 이미 계산해 둔 값.
          share 가 정밀한 채널(ap)에선 중복 기미, rwh 에선 보완(+4), rw 에선 소음(제외)

rig     = 매칭 항의 라벨열에서 `*`(와일드카드) 아닌 라벨 수
          예: f_equal `?f ?x = ?f ?y` → [=,*,*,*,*] → rig 1 (초일반)
              PTree.gso → [=,get,*,set,…] → rig 4 (특정적)
          Baire 논증: 통과확률 ≈ b^(−rig) → rig ∝ −log₂P = 말뭉치 없는 IDF
          직관: "이렇게 특정적인데도 지금 맞았다 = 우연이 아니다" 보너스
```

## 선택의 근거 (전부 TRAIN)

  (k↓ = 곡률↑ = 상위 동의에 민감).

  ap 78 · in 66 · rwh 52 는 S1rrf, **rw 만 S2rrf 65 > S1rrf 64** —
  redex 매칭에선 lcp(트리 접두사)가 share(z)와 중복 신호라 노이즈.
  "채널별로 달라도 된다"는 자유가 실제로 갈라낸 유일한 지점.

## 그외 계열의 해석 — 낮은 수치는 하한이다

§7 표의 그외 행(회수 8~16%)은 **분모가 배포 설계와 다르다**: 표는 우리
4채널 풀 안에서 재지만, §4 지침상 그외는 5번째 **tf-idf 블록**(전 우주,
필터 없음)이 담당한다. 따라서 **진짜 질문은 "tf-idf 블록이 그외 골드를
top10/20 에 넣는가"** 이고, 현재 그외 행은 그 하한일 뿐이다.

낮은 이유도 구조적이다 — 그외는 "goal 과의 단일화"라는 후방 적용가능성
관계의 밖에 있다:

| 형태 | 왜 4채널 밖인가 | 실제 커버 경로 |
|---|---|---|
| unfold (최다) | 대상이 정리가 아니라 **정의** — A/P/R 색인 대상 아님 | ★ 프롬프트의 [TYPES]/[DEFINITIONS] 섹션이 이미 커버: goal 결론의 식별자를 시드로 **정의 본문을 재귀 주입** (stdlib 제외 — 모델 사전지식). unfold 는 검색 문제가 아니라 문맥 선택 문제 |
| destruct·case | 결정 정리(`lt_eq_lt_dec`)를 **전방**으로 던져 분기 — 결론(sumbool)이 goal 과 단일화할 이유 없음 | tf-idf 블록 |
| elim·induction | 귀납원리 — 대상 항 타입에서 나오는 스킴 | tf-idf 블록 + 문맥 |

### 후속 아이디어 (우선순위순, 미착수)

- **A. 측정 정합**: 그외 행을 전 우주 rango tf-idf 로 재기 — sentence DB
  이름→선언 일괄 dict(0.7s 실증) + goal 사이드카로 오프라인 계산 가능.
  §7 표가 5블록 배포의 기대 성능을 정확히 시뮬레이션하게 된다.
- **B. dec 채널**: destruct/case 용 전방 채널(결론 머리 sumbool/or/ex 색인,
  결론 인자↔goal 부분항 단일화). 플러그인 dc 뼈대 존재. A 측정 후
  tf-idf 블록이 못 담는 양이 크면 그때 — §4 깨끗함과 트레이드오프.
- **C. unfold**: 위 표대로 이미 프롬프트가 커버 — 채널 불필요 재확인.
- **D. SFT 쪽**: §2 의 gold 주입(top-20 랜덤 삽입) 옵션.

## 프롬프트 주입 범위와 retrieved premise 의 타입 정의 (2026-09-02 결론)

현행 주입 범위 (augment.py 실측 확인):

```
[TYPES]        시드 = 가설 + 결론 (hyp_types 최우선 → 결론 식별자 · 재귀 depth)
[DEFINITIONS]  시드 = 결론의 식별자만
extra_seeds    임의 추가 훅 (Constructor 12.2%·Field 17.4% 공백 실측으로 신설)
```

"applicable premise 의 시그니처 기호가 이미 프롬프트에 있나" — 부분적으로만:
**매칭부**(결론↔goal · 패턴↔redex)는 단일화 덕에 goal-시드가 커버 ✓,
**전제(side condition)·rewrite 반대변**은 goal 에 없는 새 기호 가능 ✗.

**결론: retrieved premise 의 타입 정의는 주입하지 않는다.**
1. 갭이 있어도 premise 를 *고르는* 데는 [Premises] 의 진술문 텍스트로 충분
   (시그니처는 보임 — 본문 정의까지 필요한 경우는 드묾)
2. 토큰 예산 실측: 후보 92.7% stdlib · [PREMISES] 10~22개 예산 — 정의 주입은
   곧 premise 개수 감소
3. 재검증 쉬움: extra_seeds 에 premise 머리를 넣는 ON/OFF A/B 가 한 줄 —
   SFT 실험 때 옵션으로, 기본 OFF
