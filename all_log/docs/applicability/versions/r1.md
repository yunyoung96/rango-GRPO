# r1 — `assert_succeeds` 배터리

> 플러그인 이전. **Coq 안에서 tactic 을 실제로 실행해 보고 상태를 되돌린다.**

## 바꾼 것

- 후보 이름마다 이 한 줄을 `.v` 파일에 이어붙여 `coqc`/`coqtop` 에 먹인다:

```coq
first [ assert_succeeds (first [
          eapply L | erewrite L | erewrite <- L
        | erewrite L in * | apply L | rewrite L ]); idtac "OK L" | idtac ].
```

## 왜

- `experiment.txt §36-4` 가 *"진짜 결정적 술어는 `apply` 가 실제로 성공하는가이고
  그건 Coq 을 돌려야 안다"* 고 적었다. **Coq 안에서는 그게 한 줄이다.**
- 판정이 elaboration·변환(δι)·evar·강제변환·타입클래스를 **전부 포함한 커널 단일화 그 자체**다.

## 실측

| | |
|---|---|
| 후보당 비용 | **0.11ms** (263개 496ms, 그중 470ms 는 Coq 기동) |
| 축소 | 262 → 22.6 (**12배**) |
| gold 생존 | 80.8% |
| `eapply` 하나만 쓸 때 | 52배 축소지만 gold 생존 **73.1%** — 형태를 여러 개 봐야 한다 |

## 함정

- **`eapply L in *` 는 문법 오류다** (`in` 은 rewrite 계열만). 하나라도 파싱이 깨지면
  파일 전체가 죽어 **전부 0** 이 된다. 실측으로 걸렸다.
- `coqc` 는 오류에서 파일 처리를 **중단**한다 → 뒤 후보를 통째로 잃는다.
  (r2 이후 플러그인으로 옮기며 사라진 문제)

- 후보 하나마다 증명 상태를 저장·복원하므로 0.11ms 가 든다.
