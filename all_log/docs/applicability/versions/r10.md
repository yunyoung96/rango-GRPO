# r10 — `rewrite` 를 goal 쪽과 가설 쪽으로 가른다

> 이전: [r9](r9.md) · 다음: [r11](r11.md) · 결과: [../results/r10.md](../results/r10.md)

## 바꾼 것

**`rw` 채널을 `rw`(goal) 과 `rwh`(가설) 로 분리했다.**

```ocaml
let goal_sub = CH.create 97 in
let rec mark t = CH.replace goal_sub (Unsafe.to_constr t) (); EConstr.iter sigma mark t in
mark concl;                                    (* goal 부분항에 표시 *)
…
(if CH.mem goal_sub (EConstr.Unsafe.to_constr st)
 then Hashtbl.replace out_rw  nm ()            (* rewrite L      *)
 else Hashtbl.replace out_rwh nm ());          (* rewrite L in H *)
```

같은 트리·같은 스캔을 쓰고 **맞은 redex 의 출처로만** 가른다.

## 왜

실측이 둘을 다른 집합으로 만들었다.

```
   goal redex 로 통과      163
   가설 redex 로만 통과    147
   교집합                    0     ← 완전히 겹치지 않는다
```

비중도 6배 다르다 (`rewrite` 22.1% vs `rewrite … in` 3.8%).
한 채널로 묶으면 슬롯 배분이 어긋난다.

## 실측 (CompCert · `PTree.gso` goal)

| 채널 | r9 | **r10** |
|---|---|---|
| apply | 349 | 349 |
| apply…in | 456 | 456 |
| rewrite(goal) | 310 | **268** |
| rewrite(hyp) | — | **147** |
| unfold | 4 | 3 |
| destruct | 3 | 3 |
| decide | 91 | 91 |

gold `PTree.gso` 는 `rw` 쪽에만 들어간다 — 분리가 옳게 됐다.

### 좌·우변 둘 다 덮는지 Coq 에게 확인

```coq
Lonly_l : z + 0 = z * 1     goal 에 z+0  →  rewrite Lonly_l     OK
Lonly_r : z * 1 = z + 0     goal 에 z+0  →  rewrite <- Lonly_r  OK
                                            rewrite Lonly_r     NO
둘 다 CHECK rw=1 로 잡힌다.
```

R 색인의 태그가 `깊이*2 + 변` 이라 방향을 복원할 수 있다 —
**채널을 더 안 만들어도 된다.**

## 함정

`DNRWH` 출력을 파이썬 파서가 **안 잡고 있었다.** 정규식 교대를
`DNRW|…` 순으로 둬서 `DNRWH foo` 가 `DNRW` 로 맞은 뒤 공백을 못 찾아
**줄 전체를 버렸다** — 가설 rewrite 후보 147개가 통째로 사라졌다.

```python
r"^(APPLICIN|APPLIC|DNRWH|DNRW|UNFOLD|DESTRUCT|DECIDE) …"
                    ▲ 긴 것을 먼저
```
