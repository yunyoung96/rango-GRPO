# 판별트리는 실제로 어떻게 생겼나

> 그림만 보고 이해하도록 만든 문서. 이론은 [btermdn.md](btermdn.md),
> 거리는 [baire.md](baire.md), 한계는 [limits.md](limits.md).

---

## 1. 한 줄 요약

```
   lemma 수천 개                  goal 하나
        │                            │
        ▼                            ▼
   ┌─────────┐   조회 한 번    ┌──────────────┐
   │ 판별트리 │ ───────────▶  │ 후보 수백 개  │
   └─────────┘                └──────────────┘
   12,652개                        596개
```

전부 훑으면 12,652번 단일화해야 한다. 트리는 **한 번 내려가서** 596개로 줄인다.

## 2. lemma 하나가 트리에 들어가는 과정

```coq
PTree.gso : forall A i j x m, i <> j ->
              PTree.get i (PTree.set j x m) = PTree.get i m
```

### ① 결론만 남긴다 (Π-바인더·전제를 벗김)

```
   forall A i j x m,  i <> j  ->  get i (set j x m) = get i m
   └───── 벗김 ─────┘ └ 벗김 ┘     └────────── 남음 ──────────┘
```

### ② `rewrite` 색인이면 등식의 **양변**을 각각 넣는다

```
       eq  _  (get ?i (set ?j ?x ?m))  (get ?i ?m)
                └──── 좌변 ────┘        └ 우변 ┘
                     ↓                    ↓
                 태그 (0,좌)           태그 (0,우)
```

### ③ 각 변을 **전위 순회 라벨 열**로 편다

```
   get ?i (set ?j ?x ?m)

              get/2                    ← 라벨 = (이름, 인자수)
             ╱     ╲
           ?i      set/3
                 ╱  │  ╲
               ?j  ?x  ?m

   전위 순회:  [ get/2 , * , set/3 , * , * , * ]
                                     └ ?는 전부 `*` (와일드카드)
```

### ④ 그 열을 트라이 경로로 써서 값을 매단다

```
   (뿌리)
     └─ get/2
          └─ *
              └─ set/3
                   └─ *
                       └─ *
                           └─ *  ●  ← 여기에  (PTree.gso, 태그(0,좌))
```

## 3. 여러 개가 들어가면 — 접두사가 공유된다

넣을 것:

```
   PTree.gso   좌: get ?i (set ?j ?x ?m)      우: get ?i ?m
   PTree.gss   좌: get ?i (set ?i ?x ?m)      우: Some ?x
   PTree.grs   좌: get ?i (remove ?i ?m)      우: None
   Z.add_0_r   좌: ?n + 0                     우: ?n
   f_equal     좌: ?f ?x                      우: ?f ?y     ← 머리가 변수!
```

```
                            (뿌리)
        ┌──────────────┬──────────┬───────────────────┐
     get/2           add/2       *                   Some/1 …
        │              │         │
        *              *         ● {f_equal, eq_sym, …}
   ┌────┴────┐         │            ▲
 set/3   remove/2      0            └ 머리가 변수인 lemma 는 전부
   │        │          ●              여기 한 자리에 쌓인다
   *        *      {Z.add_0_r}
   │        │
   *        ● {PTree.grs}
   │
   *
   ●
{PTree.gso, PTree.gss}     ← 좌변 모양이 같아 같은 노드에 모인다
```

**세 가지를 읽을 수 있다.**

1. `gso` 와 `gss` 는 **끝까지 붙어 있다** — 트리로는 못 가른다.
   가르는 건 나중에 커널 단일화(`?i` vs `?j`)가 한다.
2. `Z.add_0_r` 은 **1층에서 갈라진다** — 조회가 `get` 으로 시작하면 즉시 죽는다.
3. `f_equal` 은 **`*` 가지**에 있다. `*` 가지는 **어떤 조회에서도 살아남는다.**

## 4. 조회 — goal 을 들고 내려간다

goal:

```coq
PTree.get i (PTree.set j x m) = PTree.get i m
```

왼쪽 부분항 `get i (set j x m)` 으로 조회한다.

```
   조회 열:  [ get/2 , * , set/3 , * , * , * ]

   층  조회 라벨     살아있는 가지                        후보
   ── ──────────  ─────────────────────────────────  ──────────────
    0  get/2       get/2 ✓   add/2 ✗   Some/1 ✗       ─
                   *     ✓  ← 언제나                   f_equal, eq_sym
    1  *           *     ✓                             ─
    2  set/3       set/3 ✓   remove/2 ✗                ─
    3  *           *     ✓                             ─
    4  *           *     ✓                             ─
    5  *           *     ✓  ● 도착                     gso, gss

   결과 = {gso, gss}  ∪  {f_equal, eq_sym, …}
          └ 진짜 후보 ┘   └─ `*` 가지의 상비군 ─┘
```

### 왜 `*` 가지가 항상 붙어 오나

`f_equal : ?f ?x = ?f ?y` 의 좌변은 머리가 **변수**다. 무엇과도 맞을 수 있으므로
트리가 가를 수 없다. 이게 **applic-idf 가 필요한 이유**다 —
어디에나 나오는 후보는 `−log₂P ≈ 0` 비트, 즉 **정보가 없다.**

```
   조회 A ─┐
   조회 B ─┼─▶  f_equal  (전부 통과)  →  0 bit  → 랭커가 눌러야 한다
   조회 C ─┘

   조회 A ─────▶  PTree.gso (드물게 통과) →  6.3 bit → 위로 올려야 한다
```

실측: **191개 lemma 가 90% 이상 지점에서 살아남는다.** 지점당 후보의 16.2%.

## 5. `Everything` — 가름을 포기하는 자리

조회 항 안에 **펼칠 수 있는 상수**나 **evar** 가 있으면 그 자리에서 가르기를 포기한다.

```
   조회 열이 이렇게 되면:   [ get/2 , ⊗ , … ]
                                     ↑ Everything

   ┌────────────────────────────────────────────┐
   │  그 자리의 **모든 가지**로 다 내려간다        │
   │                                            │
   │        *      set/3    remove/2   cons/2   │
   │        │        │         │          │     │
   │        ▼        ▼         ▼          ▼     │  ← 전부 따라감
   └────────────────────────────────────────────┘
```

`skip_arg` 가 **부분항 하나를 통째로 건너뛴다.** 라벨에 인자 개수가 붙어 있어서
몇 층을 건너뛸지 알 수 있다.

```ocaml
| Some (_, m) -> skip_arg (n-1+m) …     (* 자식 m개가 더 생겼다 *)
```

이게 왜 무서운지 — 상수를 전부 투명(`ts = None`)으로 두면 **거의 모든 자리가 ⊗** 가 된다:

```
   Some empty (경직)            None (전부 투명)
   ─────────────────        ──────────────────────
   raw     29,381              raw    518,546   ← 17배
   시간      710 ms             시간   28,758 ms  ← 40배
```

`None` 은 "더 완전한 트리" 가 아니라 **트리를 끄는 것**에 가깝다.
→ [../terminology/transparent-state.md](../terminology/transparent-state.md)

## 6. 깊이 제한 — `dnet_depth`

```
   depth = 1        depth = 2            depth = 3
   ─────────    ─────────────────   ─────────────────────
   [get/2]      [get/2, *, set/3]   [get/2, *, set/3, *, *, *]

   ┌──────┐     ┌──────┐            ┌──────┐
   │get/2 │     │get/2 │            │get/2 │
   └──┬───┘     └──┬───┘            └──┬───┘
      ●            *                   *
   {gso,gss,      ┌┴─────┐          ┌──┴───┐
    grs, …}    set/3  remove/2    set/3  remove/2
   너무 넓다      ●       ●           │       │
              {gso,gss} {grs}        …       …
                                  더 좁지만 트리가 커진다
```

- 얕으면 → 후보가 많이 나온다 (거를 게 없다)
- 깊으면 → 트리가 커지고, **깊은 곳은 대개 `*` 라서 이득이 적다**

Coq 기본은 **8**, 우리는 **2**. 실측하니 **2로 충분하다** — CompCert 에서
깊이 2/4/8 의 최종 채널 크기가 **한 개도 안 변했다**(apply 349 · rewrite 268 · …).
빌드만 1.13s → 1.43s 로 느려진다.

```
   우리가 색인하는 것:  [ get/2 , * , set/3 , * , * , * ]
                         └─ 판별력 ─┘  └─── 전부 `*` ───┘
                            2층까지        더 내려가도 가를 게 없다
```

Coq 이 8을 쓰는 건 `auto` 의 hint DB 가 **사용자가 등록한 임의 패턴**을 담기 때문이다.
우리는 결론·등식 양변만 넣으므로 얕다. → [btermdn.md](btermdn.md) §5

## 7. 노드 안은 뭐가 들었나 (`clib/trie.ml`)

```ocaml
type t = Node of X.t * t T_codom.t
                 │         │
                 │         └─ Map.Make(라벨)  균형 이진트리
                 └─ 데이터 집합 (ZSet)
```

```
   Node
    ├── 데이터: { (gso, 태그0), (gss, 태그0) }      ← 이 경로에 도착한 것들
    └── 자식 맵 (라벨 → 노드)
          ├── Some(get/2)    ↦ Node(…)
          ├── Some(add/2)    ↦ Node(…)
          └── None (`*`)     ↦ Node(…)
```

- 배열도 해시도 아니다. **라벨로 정렬된 맵**이다. 라벨 비교는
  `GlobRef.CanOrd.compare` — 모듈 별칭을 정준 이름으로 맞춰서 본다.
- **불변(immutable)** 이다. `add` 는 경로 위 노드만 새로 만들고 나머지는 공유한다.
- 데이터가 **집합**이라 같은 경로의 lemma 가 한 노드에 모인다.

## 8. 우리 색인은 셋이다

```
   ┌── dn_apply ──────────────────────────────────┐
   │  넣는 것: 결론(과 그 화살표 접미사들)           │
   │  키:      (후보번호, 깊이)                     │
   │  조회:    goal 의 결론                         │
   └──────────────────────────────────────────────┘
   ┌── dn_prem ───────────────────────────────────┐
   │  넣는 것: **비의존** 전제                      │
   │  조회:    각 지역 가설             (apply … in) │
   └──────────────────────────────────────────────┘
   ┌── dn_rw ─────────────────────────────────────┐
   │  넣는 것: 등식·setoid 관계의 **좌·우변**        │
   │  키:      (후보번호, 깊이*2+변)                 │
   │  조회:    goal / 가설의 **닫힌 부분항** 전부     │
   └──────────────────────────────────────────────┘
```

`rewrite <-` 를 위해 채널을 따로 만들 필요가 없다 — **양변을 다 넣었기 때문**이다.

```coq
Lonly_l : z + 0 = z * 1     goal 에 z+0  →  rewrite Lonly_l     OK
Lonly_r : z * 1 = z + 0     goal 에 z+0  →  rewrite <- Lonly_r  OK
                                            rewrite Lonly_r     NO
둘 다 CHECK rw=1 로 잡힌다 (실측 확인).
```

## 9. 트리는 끝이 아니다 — 상한만 준다

```
   ┌──────────────────────────────────────────┐
   │  트리 lookup          raw   34,461       │  구문, 유한 깊이 → 과대근사
   │   ↓ 값싼 선별(suffix_compat)              │
   │  keypass               5,821             │
   │   ↓ 커널 단일화(w_unify)                  │
   │  진짜 후보               596             │  의미, 정확
   │   ↓ 랭커                                 │
   │  프롬프트 상위 10           10            │
   └──────────────────────────────────────────┘
       12,652 → 34,461* → 5,821 → 596 → 10
       (*접미사·양변 때문에 후보 수보다 커진다)
```

순서를 뒤집어 커널을 먼저 쓰면 못 쓸 만큼 느리고, 트리만 쓰면 오탐이 남는다.
**트리 → 커널** 순서만 건전하다.
