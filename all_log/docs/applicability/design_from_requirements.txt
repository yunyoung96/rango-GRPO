[1. 프롬프트 구성] 에 대한 답
────────────────────────────────────────────────────────

■ 지역 가설 익명화 — **하지 말 것을 추천**

  근거 3개:
  ① 지역 이름(H, H0, IHn)은 상태마다 다시 태어나는 이름이라 "암기" 위험이
     없다 — 전역 lemma 암기와 문제 구조가 다르다. 모델이 하는 일은 암기가
     아니라 **화면에 보이는 이름의 참조**다.
  ② gold 의 절대다수가 지역 가설을 인자로 쓴다(destruct H, rewrite IH…).
     익명화하면 상태 표시 ↔ tactic 출력의 대응을 한 겹 더 배워야 해서
     난이도만 오른다.
  ③ IHn(귀납가설)·Heq 같은 관용 이름은 그 자체가 의미 신호다.
  단, 일관성 하나만 강제: 프롬프트 상태 표시에 쓰인 이름 그대로 tactic 이
  참조하게 한다 (익명화 없음 = 자동으로 성립).
  전역 lemma 익명화는 계획대로 진행하되 stdlib 제외 ✓ — 이전 실측(Ltac
  회상 61.5% 익명화O vs notation 53.5% 익명화X)도 전역 이름에 한한 결론.

■ 섹션당 10개 vs 20개 — **비대칭 추천: ap/in/rw/Others = 10 · rwh 만 20**

  r19 자기채널 실측(@10 → @20 이득):
      apply       87 → 92   (+5)
      apply-in    63 → 71   (+8)
      rewrite     77 → 82   (+5)
      rewrite-in  53 → 68   (+15)  ← 여기만 이득이 압도적
  토큰 비용: premise 1개 ≈ 25~40tok → 블록 +10개 ≈ +300~400tok.
  전 블록 20개면 +1.2~1.6k tok 로 [PROOFS]/[STATE] 예산을 잠식한다.
  rwh 만 20개로 하면 +0.4k 로 rwh 의 +15pp 를 산다. (원하면 전블록 10 vs
  비대칭 A/B 한 번으로 확정 — 측정 인프라는 이미 있음)

■ 블록 안 순서 = 랭킹순 유지 (순위 자체가 신호다. 셔플 금지)

[2. sft 학습 프레임워크] 에 대한 답

■ case A (정답이 프롬프트에 있음) — 설계 그대로 승인. 주의 2개:
  ① 다중 gold(rewrite A, B)는 **전부** 있어야 case A — 우리 표의 All 열이
     그 판정 기준이다 (Any/All 인프라 재사용).
  ② "있음" 판정은 익명화 후 이름 기준(동일 익명화 맵 통과 후 비교).

■ case B (없음 → 주입) — 골격 승인 + 설계 디테일 3개:
  ① 제거 대상은 **블록의 하위권에서** 뽑아라 (상위 제거는 프롬프트 분포를
     배포 분포에서 멀어지게 한다).
  ② 주입 위치는 **균등 랜덤** — 고정 위치(꼴찌 등)는 위치=정답 신호로 새어
     "위치만 보는" 모델을 만든다.
  ③ 채널 정확성(지적한 그대로): FORM_CH 매핑을 단일 소스로 —
        apply/eapply/exact/eexact → [PremisesForApply]   (r17 에서 exact 편입)
        apply … in → [PremisesForApplyIn]
        rewrite → [PremisesForRewrite] · rewrite … in → [PremisesForRewriteIn]
        그 외 형태 → [Others]
     구현은 수집기·랭커가 쓰는 FORM_CH 를 import 해서 쓰고, 별도 매핑을
     복제하지 말 것(어긋나면 조용히 오염 — 우리가 이미 당해 본 부류).
  ④ 주입 premise 의 본문은 실제 선언문(선언 DB)으로 — 형식이 다른 항목은
     그 자체가 "이게 정답" 신호가 된다.

[3. gold tactic 변형] — "판별트리 기반 뚜렷한 규칙" + Qed 직접 검증
────────────────────────────────────────────────────────

핵심: **변형은 문법 규칙표로 만들고, 채택은 실행이 판정한다.**

  1단 · 변형 후보 생성 (순수 구문 규칙, 채널별):
     apply L      ⇒ eapply L                        (항상 후보)
     eapply L     ⇒ apply L                         (탈-evar 가능할 때만)
     apply L      ⇒ apply L with (x := t)           (검증의 evar 해에서 t 획득)
     apply L      ⇒ exact (L t₁ … tₙ)               (완전 적용꼴)
     rewrite H    ⇒ rewrite -> H · erewrite H
     rewrite H    ⇒ rewrite <- H′                   (등식 방향 반전)
     rewrite H    ⇒ rewrite H at n / in ⋆           (출현 지정)

     ★ 채택 기준 = **직접 실행으로 Qed 확인** (요구사항):
       변형 t′ 로 gold 스텝을 갈아끼운 뒤, **그 지점 이후의 원본 proof
       스텝들을 전부 이어 실행해 Qed 가 안전하게 찍히는지** 확인한다.
       통과한 변형만 채택. (라벨열 해시 비교는 빠른 1차 선별로만 쓰고,
       최종 판정은 언제나 Qed 직접 실행이다 — 해시 동치는 필요조건일 뿐
       충분조건이 아니다: evar 인스턴스 차이가 뒤 스텝에서 터질 수 있다.)

  2단 · **학습 전 사전 대량 생성** (오프라인 물질화) — 설계:

     산출물   all_log/sft_variants.jsonl
              {proj, thm, thmi, k, orig, variant, qed: true, rule: "ap→eapply"}
              — SFT 생성기는 이 파일을 조인만 하면 된다 (학습 중 Coq 호출 0)

     파이프라인 (기존 수집기 인프라 재사용):
       정리 단위 워커: coqtop 1세션에서
         ① head 1회 로드 (비용 상각)
         ② 원본 proof 재생하며 각 지점에서 규칙표로 변형 후보 나열
         ③ 후보마다: Abort → 정리 재시작 → k-1 스텝 재생 → 변형 t′ 실행
            → 이후 원본 스텝 전부 실행 → Qed 시도
            (probe_ok 식 1차 선별로 명백 실패는 ③ 전에 걸러 비용 절약)
       비용 추정: 변형당 ≈ 정리 1회 재생 (~수 초). 지점당 변형 ≤3,
       -in·rewrite 지점 우선. TRAIN 전체 ~2k 지점 × 3 ≈ 6k 재생
       ≈ 워커 4개로 하룻밤 규모 — 야간 배치로 1회 굽고 재사용.
       안전장치: 정체 coqtop 컷(mckill†) · 진행률 로그 · 산출 행 assert
       (qed=true 만 기록 · 좌표 중복 금지 · orig ≠ variant).

     셔플: 지점당 변형 ≤3(원본 포함), 생성 후 지점 단위 전역 셔플
     (같은 지점의 변형이 이웃 배치되면 대조 암기가 일어난다).

  † mckill = 수집 인프라의 정체 coqtop 강제종료 감시 스크립트
    (math-classes 정리 1개가 30분씩 세션을 잡던 사건 뒤 도입 —
    N분 초과한 수집용 coqtop 을 자동 kill 해 배치가 계속 흐르게 한다).

[4. 틀린 답 페널티 · 3계층 DPO · error message] 에 대한 답

■ 미검색 lemma 사용(환각)도 **학습으로** 다룬다 (제약 디코딩 안 씀 — 지시).
  방법: 아래 3계층 DPO 의 최하위 계층("아예 실패")에 환각 출력을 포함시켜
  자연스럽게 눌리게 한다. rollout 에서 프롬프트 밖 lemma 를 쓴 출력은
  실행 검증에서 어차피 실패(case A 오류)로 분류되므로 별도 라벨러가
  필요 없다 — 실행이 곧 라벨이다.

■ 3계층 선호 DPO — "실패 ≺ 성공-비gold ≺ gold 사용" 설계:

  계층 정의 (rollout 출력을 coqtop 실행으로 자동 라벨링):
     T0 실패        tactic 이 에러 (환각 lemma 포함)
     T1 성공-비gold  tactic 은 적용됨(진행) — 그러나 gold lemma 미사용
     T2 gold 사용    gold lemma(익명화 후 이름)를 쓰고 적용도 성공

  DPO 는 쌍별이므로 계층을 쌍으로 편다 (per prompt, 가용한 계층에서 표집):
     (T2 ≻ T1)  가중 1.0   ← 정보량 최대 (가장 가까운 경계)
     (T1 ≻ T0)  가중 0.7   ← "적용이라도 되는 쪽" 을 배움 = 환각 억제
     (T2 ≻ T0)  가중 0.3   ← 쉬운 쌍, 소량만 (없으면 초반 안정성 저하)
  가중은 손실 계수 또는 표집 비율로 구현 (표집 비율 권장 — 구현 단순).
  margin 형 변형(예: DPO+margin, T2−T0 쌍에 큰 margin)은 2차 실험으로.

  쌍 채굴 파이프라인:
     5k SFT 라운드마다: 프롬프트당 k=4 rollout → 실행 라벨링(T0/T1/T2)
     + 규칙 기반 보강: T1 이 안 나온 프롬프트에는 **랭킹-이웃 치환**
       (gold 와 같은 블록의 상위 비정답 lemma 로 tactic 치환) 을 실행해
       성공하면 T1 로, 실패하면 T0 으로 편입 — 라벨은 역시 실행이 정한다.
     프롬프트당 최종 쌍 ≤2개 (과표집 방지), 라운드당 쌍 수 ≈ SFT 표본의 10%.

  스케줄 (질문의 "60k 중 5k 마다"에 대한 구체안):
     SFT 5,000 → DPO 500~1,000 → SFT … 반복 (비율 ~10:1)
     · reference = 직전 SFT 스냅샷으로 매 라운드 갱신
     · DPO LR = SFT 의 1/5~1/10 · β 0.1~0.3 시작
     · 끝에 몰아서 하는 DPO 는 부적합 (분포가 굳은 뒤 교정 불가) — 지적대로

■ error message 섹션 설계:

     [ErrorFeedback]
     none                            ← 평시 SFT (섹션 헤더는 항상 존재)

     [ErrorFeedback]
     prev: apply lt_le_trans.
     error: Unable to unify "?y < ?z" with …    ← 재시도 학습/추론 시

  헤더를 항상 두는 이유: 추론 루프에서 에러 후 재시도할 때 같은 형식에
  내용만 채우면 되고, 학습·추론 간 형식 스위치가 없어야 한다. <empty>
  같은 인공 토큰보다 `none` 한 단어가 낫다(자연어 사전확률 활용).
  데이터: 탐색 루프 로그의 (상태, 실패 tactic, error, 이후 성공 tactic)
  으로 2차 SFT — T0 rollout 이 그대로 이 데이터의 공급원이 된다.

[6. 설계 리뷰 — 추가 피드백 5건] (2026-09-02)
────────────────────────────────────────────────────────

① (T2≻T1) 쌍의 함정 — **정당한 대안 경로 벌점 금지** ★최중요
   "성공-비gold"는 동급 정답일 수 있다(gold 는 인간의 선택이지 유일해가
   아니다). 처방: T1 후보에 Qed-검증을 재사용 — 그 수 이후 증명이 실제로
   이어지면 **쌍에서 제외**(그건 대안 정답이다). 벌점은 "적용은 되나
   증명이 안 이어지는" 진짜 막다른 수에만 준다.

② error message 도 익명화 — Coq 에러는 실명을 담는다
   ("Unable to unify … lt_le_trans"). [ErrorFeedback] 주입 전에 프롬프트와
   **같은 익명화 맵**을 통과시킬 것 — 안 하면 이 구멍으로 익명화가 무력화.

③ 주입 100% 의 분포 왜곡 — 학습은 "정답이 항상 블록에 있음", 배포는
   60~92%. 3계층 DPO 가 완화 장치지만 모니터 지표를 상설한다:
   "모델이 고른 premise 가 프롬프트 안에 있는 비율" (배포·평가 공통).

④ 토큰 예산은 실측으로 — STATE+PROOFS+TYPES/DEFS+5블록(≈50개)+
   ErrorFeedback 합산이 기존 hard_seq_len 3072 를 넘길 공산이 크다.
   학습 전 스모크에서 섹션별 예산표를 찍고 3072 유지/4096 확장을 결정
   (잘림은 조용한 성능 하락 — 과거 lenscan 실측 참조).

⑤ 평가 프로토콜 선고정 — 기준선(next_step top-k=39.2% · rand200 증명률)을
   학습 전 재측정해 두고, rand200 은 **워커 수 고정**(실측: 워커수 confound,
   w2 33~37.5 vs w6 28~32.5 — 실패의 100%가 600s timeout).

[7. 학습 직전 체크리스트 · steps 산정 · 셔플] (2026-09-02)
────────────────────────────────────────────────────────

■ 셔플 (요구 반영): 물질화 직후 **지점 단위 전역 셔플** — 같은 지점의
  원본·변형 행이 이웃하지 않게 지점 키로 그룹 셔플 후 그룹 내부도 셔플.
  sft_build 가 산출 단계에서 수행 (학습 로더의 셔플에만 의존하지 않는다 —
  파일 순서 자체가 안전해야 재현이 쉽다).

■ steps 산정 — 60k 는 부족할 공산:
  전체 dp ≈ 2M 스텝 중 외부참조(4형태+그외) ≈ 15~20% → 30만~40만 지점,
  변형 ×~1.3 → 표본 ~40만~50만 행. batch 8 기준 1 epoch ≈ 5만~6만 step
  → **60k ≈ 1 epoch 뿐**. 권고: 물질화 완료 후 실측 표본수로
  2~3 epoch = **120k~180k steps** 재산정 (변형·주입의 다양성이 과적합을
  완화하므로 epoch 증가가 정당). lr 스케줄(cosine)도 총 step 에 맞춰 재설정.

■ 학습-전 체크리스트 (차례대로, 각 단계 assert·스모크 통과 후 다음):
