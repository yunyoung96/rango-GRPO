# 실험 세팅 비교 — 원조 rango vs 멈춘 v11(3-epoch) vs 진행 중 v11-rango식(60k)

작성 2026-09-02 19:2x KST. 근거 파일: `all_log/ft_rango_augmented_conf.yaml`(원조 재현 설정),
`all_log/ft_qwen3_4b_v11_conf.yaml`, r19_v2 수집 로그, design_from_requirements.txt.

## 용어 먼저

- **유효배치(eff batch)** = per_device_batch × grad_accum × GPU 수. 한 step 에서 gradient 를 계산하는 행 수.
- **표본(examples seen)** = steps × 유효배치. 학습이 "본" (프롬프트→정답) 쌍의 연인원.
- **epoch** = 표본 ÷ 데이터 행 수. 같은 행을 평균 몇 번 보나.

## 질문별 상세

### 1. 배치 크기가 다른가? — **아니요, 유효배치는 셋 다 32로 동일합니다.**
다른 것은 분배 방식뿐: 원조는 per-device 4×accum 4, 우리는 per-device 2×accum 8.
낮춘 이유 = 메모리 안전(5120 토큰·4B 풀FT에서 per-device 4는 피크 79GB/96GB → 2로 낮춰 ~55GB).
gradient 는 accum 으로 합산되므로 수학적으로 동등합니다.

### 2. epoch 차이는 왜 나나? — **분모(데이터 행 수)가 다르기 때문입니다.**
- 원조: 1.92M 표본 ÷ 1.53M 행 ≈ 1.25 epoch — "거의 모든 데이터를 대략 한 번" 보는 체제.
- 멈춘 세팅: 데이터가 81k 행(수집 상한·필터·정제로 축소)이라 같은 60k step 을 돌리면 24 epoch(과적합) →
  3 epoch 로 잡아 7,593 step 이 된 것. **step 이 적었던 게 아니라 데이터가 작았던 것.**
- rango식(진행 중): 상한을 풀어 행을 ~15만으로 키우고 60k 고정 → **11~13 epoch** (밀도 실측 보정).
  ※ 원조의 1.25 epoch 까지 못 내려가는 이유: 원조는 TRAIN 전체(150+ 저장소)를 쓰지만, 우리 5블록 프롬프트는
  **applicability 필터 = 저장소 컴파일**이 전제라 빌드 가능한 44 저장소(+상한 해제)로 데이터 천장이 있습니다.
  (그 천장을 더 올리는 길 = 캠페인 확장·외부 라이브러리 의존 해결 — future_work.)

### 3. 데이터 개수·구성 차이
- 원조: dp 의 **모든 스텝**을 학습 시점에 즉석 물질화(tf-idf [PREMISES] 100개). 선별·검증·주입 없음.
- 우리(공통): 수집기(r19 필터) → 물질화 v2 → **정적 C1~C17 + 동적 D1~D3 + Qed 검증 변형** 을 통과한 행만.
  멈춘 세팅 82,636행 = A 11.5k · B 5.8k · 무참조 41.8k · 변형 24.0k (상한: 정리당 외부참조 ≤8·무참조 ≤4 —
  ※ 이 상한은 rango 논문에 없는 **우리 수집기의 비용 통제**였다(필터 250ms/지점 × 거대 증명 잠식 대응).
  rango 는 표본화 없이 전 스텝 사용 — 무상한 수집이 그 방침으로 되돌린 것).
  rango식 = 상한 제거(전 스텝) → 정리당 평균 3.7→~7지점(실측), 행 ≈13만~17만 전망 · 변형 저장소(63,237) 조인 포함.

### 4. "표본"이 왜 중요한가
loss 하강과 암기/일반화의 트레이드오프는 (표본, epoch) 축에서 결정됩니다. 같은 60k step 이라도
분모가 작으면 같은 행을 24번 외우는 학습이고, 분모를 키우면 11~13번 수준으로 내려갑니다(천장 = 컴파일 가능 44저장소).
사용자 결정(2026-09-02): rango 식 — 분모를 키워 epoch 를 내리고 step 을 60k 로 고정.

## 진행 중 회차의 남은 리스크 (기록)

1. **시간**: 60k × ~20s ≈ 333h(2주). 중간 이정표(5k마다 체크포인트·DPO)로 조기 평가 가능 — 10k step
   시점(≈2.3일)에 rand200 예비 평가로 계속/중단 판단 권장.
2. 11~13 epoch 는 원조(1.25)보다 크게 높음 — 15k 게이트(≈3 epoch 시점 rand200 평가)로 계속/종료를 결정 — 변형·주입의 다양성이 완충하지만, 과적합 신호(guard·샘플 EM
   포화)를 감시 지표로 봄.
3. 무상한 수집로 heavy 정리의 지점이 급증 — 프로젝트 편중은 셔플로만 완화(가중 샘플링은 미적용).
