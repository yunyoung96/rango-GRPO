# cut 보강 — 환각을 거의 없애기

> **결론**: 학습에서 환각을 **구조적으로 0 으로** 만들었다. 두 가지를 했다.
> ① 읽을 수 없는 이름을 쓰는 스텝은 **학습에서 제외**한다 (`CUT_DROP_HOPELESS=1`)
> ② 제외 대상을 **정확히** 판정하도록 고쳤다 — 제외율 **7.0% → 4.7%**
>
> 배경은 [final.md §10](final.md), 구현 디테일은 [details.md](details.md).

---

## 0. 용어

| 용어 | 뜻 |
|---|---|
| **cut** | 증명에서 보조 명제를 세워 쓰는 것. Coq 에서는 `assert (P) as H` |
| **gold lemma** | 정답 tactic 이 참조하는 이름 |
| **후보 풀 (pool)** | 검색이 훑는 premise 전체 집합. 여기 없으면 랭킹으로 못 건진다 |
| **프롬프트 포함** | 토큰 예산(896) 안에 살아남아 모델이 실제로 볼 수 있는 것 |
| **가망 없음 (hopeless)** | 정답이 **프롬프트에 없는 이름**을 쓰는 스텝 |
| **환각** | 프롬프트에 없는 이름을 정답으로 내놓는 것 |

## 1. 문제 — 실험 예고와 실제가 8pp 어긋났다

```
실험 예고 (exp_abcd.py)    A + (1-A)×C = 95.6%
실제 구축 (build_cuts.py)  ①+②        = 87.6%
```

같은 분모(gold 가 후보 풀에 있는 스텝 11,701)에서 **8.0pp** 차이다.
실험의 C 는 *명제를 만들 수 있었던 것들 사이에서만* 잰 재검색 성공률이라,
명제를 아예 못 만든 케이스가 분모에서 빠져 낙관적으로 나왔다.

**그리고 더 큰 문제가 있었다.** 가망 없는 스텝을 "정규화만 끄고" 학습에 넣고 있었다.
그건 여전히 모델에게 **볼 수 없는 이름을 출력하라**고 가르치는 것이다.

## 2. ★ 근본 수정 ① — 가망 없는 스텝을 학습에서 뺀다

정규화를 끄는 것으로는 부족하다. 이름을 **외우게 하는 것 자체**가 문제다.

```python
# src/tactic_gen/tactic_data.py
def resolved_example(self, index):
    """학습이 실제로 쓰는 예제. 가망 없는 스텝은 다음 인덱스로 치환한다."""
```

`__len__` 을 바꾸면 스케줄러·재개가 어긋나므로 **인덱스를 치환**한다.
`preflight_all.py` 의 **검사 J** 가 "학습에 들어간 hopeless = 0" 을 확인한다.

환경변수: `CUT_DROP_HOPELESS=1` (`all_log/v9_env.sh`)

> 왜 이게 맞나. 모델이 맞힐 수 **없는** 예제로 학습하면 배우는 것은 하나뿐이다 —
> "안 보여도 그럴듯한 이름을 지어내라". 추론에서 그 습관은 **반드시 실패**한다
> (없는 lemma 를 부르면 Coq 이 거부한다). 차라리 그 상황에서 보이는 premise 로
> 다른 tactic 을 시도하는 편이 탐색에 쓸모 있다.

## 3. ★ 근본 수정 ② — "가망 없음" 판정이 틀렸다

제외가 옳더라도, **무엇을 제외할지**가 부정확하면 멀쩡한 데이터를 버린다.
원래 판정은 세 가지를 오분류하고 있었다.

### 3-1. 함수·타입 이름을 lemma 로 오인 — 가장 큰 오분류

`gold_lemmas` 는 tactic 에서 **전역 이름**을 뽑는데, 그중에는 lemma 가 아니라
**함수·타입**이 섞인다.

```
unfold closure, closure2.        ← closure2 는 Fixpoint
destruct (O.eq_dec a t0).        ← eq_dec 는 Definition
rewrite -/(app [a] _) …          ← app 는 Definition
```

**실측: `need_coq` 1,149개 중 1,054개(91.7%)가 Definition/Fixpoint 였다.**

함수는 **명제가 아니라 assert 할 수 없다.** 더 결정적으로, 후보 풀은 설계상
함수를 아예 담지 않는다.

```python
# src/premise_selection/premise_filter.py
PROJ_THM_FILTER_CONF = PremiseFilterConf(
    non_coq_excludes=["DEFINITION", "NOTATION", "INDUCTIVE", "COINDUCTIVE",
                      "RECORD", "CLASS", "INSTANCE", "FIXPOINT", …],   # 전부 제외
```

**풀에는 정리(theorem)만 들어간다.** 그러니 함수 이름이 "풀에 없는" 것은
검색 실패가 아니라 **당연한 일**이다. 그걸 실패로 세면 고칠 수 없는 것을 고치려 든다.

함수 이름은 검색이 아니라 **goal 본문 · `[TYPES]` · `[DEFS]` 주입**으로 모델에 도달한다.

**수정**: `sentences.db` 전체에서 이름 → 선언 종류 사전을 만들고(229,251개),
**명제인 이름만** cut 판정에 쓴다. 함수 이름은 프롬프트에 보이는지만 확인한다.

### 3-2. 생성자를 lemma 로 오인

`S`(nat) · `I`(True) · `eq_refl`(eq) · `Zpos`(Z) · `Acc_intro`(Acc) — 전부 생성자다.
`declname` 은 `Inductive` 선언의 **타입 이름만** 뽑으므로 생성자는 사전에 없었고,
"모르는 이름 = 명제"로 처리돼 검색 실패로 세어졌다.

**수정**: `Inductive T := A | B | C` 의 본문을 파싱해 생성자를 사전에 넣고,
**생성자 → 부모 타입** 매핑도 만든다. `S` 가 goal 에 안 보여도 `nat` 이 보이면
`[TYPES]` 주입으로 `Inductive nat := O | S …` 가 통째로 따라오므로 읽힌다.

### 3-3. 가시성 검사가 goal 만 봤다

프롬프트에는 goal 말고도 `[SCRIPT]`(지금까지의 증명) 와 `[PREMISES]` 가 들어간다.
goal 만 보면 실제로는 읽히는 이름을 "안 보임"으로 잡는다.

**수정**: goal + 가설 + `[SCRIPT]` + **프롬프트에 실제로 들어가는 premise 본문**
(랭킹 후 `nfit` 개)까지 보고, 단어 경계로 매칭한다.

## 4. 효과 — TRAIN 3,000 예제 표본

| 지표 | 수정 전 | ①함수·타입 | ②생성자 | ③가시성 |
|---|---|---|---|---|
| ① 만으로 명제를 얻은 비율 | 76.0% | 96.8% | 98.0% | **99.1%** |
| cut 확보율 | 83.6% | 96.6% | 97.8% | **99.0%** |
| cut 조립 성공률 | 98.0% | 100% | 100% | **100%** |
| ② Coq 이 필요한 스텝 | 990 | 8 | 5 | **2** |
| **학습 제외율** | 7.0% | 7.0% | 7.0% | **4.7%** |

**Coq 을 한 줄도 실행하지 않고** ②의 990건이 사실상 사라졌다 —
애초에 Coq 이 필요한 문제가 아니라 **분류가 틀린 문제**였기 때문이다.

## 5. 남은 4.7% — 무엇이고 왜 못 고치나

| 사유 | 건수(3,000 표본) |
|---|---|
| 함수·타입 이름이 프롬프트에 없음 | 107 |
| gold 가 풀에 없음 | 26 |
| 기타(재검색/조립 실패) | 7 |
| Coq 필요 | 2 |

못 읽는 이름 167개 중 **stdlib 63 · 프로젝트 104**.

```
le_trans · mult_assoc · mul_comm · proj1 · CRmin_sym   ← stdlib lemma
HH · IHn' · eps · iN · lt7                              ← 지역 가설(파서 오추출)
```

**stdlib lemma 는 원리적으로 못 읽는다.** `PROJ_THM_FILTER_CONF.coq_excludes` 가
`THEOREM`·`LEMMA` 를 포함해 **stdlib 정리를 풀에서 통째로 제외**하기 때문이다.
rango 의 원래 설계가 "stdlib 은 모델이 안다"고 가정한 것인데,
**프로브로 확인한 바 모델은 stdlib lemma 를 모른다**(F1 0.292 vs 가짜이름 0.291).

→ 고치려면 **후보 풀에 stdlib 정리를 넣어야 한다.** 풀 크기가 크게 늘고
A/B/C 실험을 전부 다시 재야 하므로 이번 학습에는 넣지 않는다. [future-idea.md](future-idea.md) 참조.

**판단**: 남은 4.7% 는 **제외한다**. 데이터를 4.7% 잃지만, 그 대가로 학습 중
환각이 구조적으로 사라진다. "환각은 거의 없는 게 좋다"는 요구에 맞춘 선택이다.

## 6. ★ Coq 경로가 막혀 있다 (그리고 이제 필요 없다)

`build_cuts.py` 의 원래 설계는 명제를 두 경로로 얻는다.

```
① Coq 없이 — sentences.db 의 premise 원문을 파싱
② Coq 필요 — 그 증명 지점에서 `Check (L a b).` 실행
```

**②는 한 번도 실행된 적이 없고, 이 머신에서는 실행할 수 없다.**

| 필요한 것 | 상태 |
|---|---|
| Coq 8.18.0 (`/root/.opam/coqstoq/bin/coqc`) | ✅ 있음 |
| `coq-lsp` · `coqpyt` | ✅ 있음 |
| **학습 프로젝트 ~150개의 원본 `.v`** | ❌ **없음** |
| 그 프로젝트들의 빌드 산출물 `.vo` | ❌ 없음 |

`data/coq-dataset/data_points/*.v` 는 **파일명만 `.v`** 이고 내용은 전처리된 JSON 이다.
원문은 `sentences.db`(582,037 문장)에 이미 추출돼 있다. `CoqStoq/` 의 `.v` 5,017개는
**평가용 12개 프로젝트**(compcert, buchberger …)이지 학습 프로젝트가 아니다.

②를 실행하려면 ~150개 저장소(13G)를 다시 받아 **프로젝트마다 다른 opam 의존 버전으로**
빌드해야 한다. 며칠이 걸리고 실패율이 높다.

**→ 결과적으로 필요 없어졌다.** ②가 필요하다고 세어진 990건 중 91.7% 는
Coq 문제가 아니라 분류 오류였고, 나머지는 3,000 표본에서 **2건**까지 줄었다.

## 8. 검증 스크립트가 틀렸던 것들 — 4건 전부 오탐이었다

**검증이 실패를 뱉는다고 코드가 틀린 것은 아니다.** 이번에 잡힌 것 4건은 전부 검사 쪽 결함이다.

| 검사 | 오탐 내용 | 고침 |
|---|---|---|
| `preflight_all` **C. 라벨==정답** | 라벨을 원본 gold 와만 비교 — cut 치환은 라벨을 **의도적으로** 바꾼다 | `CUTS_PATH` 있으면 기대값을 cut 으로 |
| `verify_cut_collate` **hopeless 정규화** | 정규식 `[TfCLG]\d+` 가 원본 식별자 `f1`/`T1`/`C0` 를 오인 | 정규화 OFF 결과와 **타깃 비교** |
| `preflight_train` **evar 남음** | `rewrite ?H` 의 **반복 플래그**를 evar 로 오인 | `assert` 의 **타입 부분만** 검사 |
| `verify_cut_collate` **exact 대상이 프롬프트에 없음** | `[A-Za-z_][\w'.]*` 가 **문장 끝 마침표까지** 삼켜 `gupaco5_mon.` 을 뽑았다. `base = split(".")[-1] = ""` 가 되어 189건 전부 "없음"으로 찍혔다 | 한정이름은 살리고 종결 마침표만 제외 |

> 교훈 두 가지.
> ① "정규화되었는지"를 **결과의 생김새**로 추측하지 말고 **정규화를 끈 것과 비교**한다.
> ② 이름 정규식에 `.` 을 넣을 때는 **한정이름(`Nat.add_comm`)과 문장 종결 마침표**를
>    반드시 구분한다. 안 하면 모든 이름이 매칭에 실패하는데, 그게 "전부 실패"라는
>    **그럴듯한 결과**로 나와서 알아채기 어렵다.

## 9. 학습 속도 — 별도 문서로

보강을 마치고 본학습을 걸었더니 **85 s/step** 이었다(20,000 step 이면 20일).
GPU 가 0%↔100% 를 오가며 굶고 있었다.

원인은 `proof_ret` 이 예제마다 **의존 파일을 전부 로드**하는 것이었고,
`DatasetFile.load` 의 `metadata_only` 를 써서 **의존 로드를 132배** 빠르게 했다.
`[PROOFS]` 내용은 **바이트 단위로 동일**하다(프롬프트 30/30 일치 검증).

> ⚠ 중간에 `proof_ret` 을 **제거**하는 안을 실행했다가 되돌렸다.
> 25배로 가장 빨랐지만 `[PROOFS]` 를 비우는 것은 **rango 방법의 핵심 축을 빼는 것**이라
> 속도 선택지로 올려서는 안 되는 것이었다. 빠른 것이 아니라
> **내용을 안 바꾸면서 빠른 것**을 찾아야 했다.

→ 전체 분석·실측·교훈은 **[speed.md](speed.md)** 에 있다.
