# 구조 정보만으로 하는 검색 — 경로집합 metric

## 0. 무엇을 하려는가

지금 랭커는 항이 셋이고, 그중 둘이 원리적 정당화가 없다.

    ① RRF(tfidf)      IR 표준. PL 의미 없음. **5,000개까지 좁히는 1차 필터**
    ② RRF(C')         head 다중집합의 IDF 가중 코사인. "왜 코사인?" 에 답 없음
    ③ W·1[⟦p⟧=⟦g⟧]   포섭 격자가 낳음. 정리 있음. 매개변수 0            ← 유일하게 예쁨

목표: **①②를 없애고 구조 정보 하나로 검색을 완결한다.**

두 가지가 필요하다.
  (a) 구조 유사도가 **진짜 거리(metric)** 여야 한다 — 그래야 인덱싱이 정당하다
  (b) 그 인덱싱이 **실제로 빨라야** 한다 — 큰 프로젝트에서 쓰려면

---

## 1. 왜 지금 것은 metric 이 아닌가

우리가 쓰던 AU-Dice `1 − F₁ = 1 − 2m/(c+n)` 는 **삼각부등식을 어긴다**
(`verify_au_props.py` P8 에서 합성 반례 확인). 그래서 "거리" 라 부를 수 없고
**영집합(핵)만** 쓸 수 있었다 — `eqx` 가 정확히 그 핵이다.

포섭 격자에서 `d = 1 − |s⊓t|/|s⊔t|` 를 그대로 쓰는 것도 안 된다.
`⊔`(단일화)가 항의 크기를 폭발시켜 값매김 `size` 가 **modular 가 아니기** 때문이다.

---

## 2. 열쇠 정리

> **Theorem 1** ([arXiv:2608.18194](https://arxiv.org/html/2608.18194))
> 임의의 격자 `L` 위 값매김 `f` 가 **strictly positive · monotone · modular** 이면
> `d_{f,J}(A,B) = 1 − f(A∧B)/f(A∨B)` 는 삼각부등식을 만족한다.

**modularity 가 필수다.** submodular 만으로는 안 되고, 그때는 대칭차 형태로 바꿔야 한다
(논문이 "이 전환은 문체가 아니라 수학적으로 강제된다" 고 못박는다).

---

## 3. 표현을 옮긴다 — 경로집합

    S(t) = { 루트→노드 심볼 경로 }          α-정규형 위에서
    d_J(s,t) = 1 − |S(s) ∩ S(t)| / |S(s) ∪ S(t)|

경로는 `심볼/자식번호/심볼/…` 로 적는다. **자식 번호를 넣어야** 위치가 구분되어
`f(a,b)` 와 `f(b,a)` 가 다른 집합이 된다.

### 왜 이게 되나

  · 멱집합 격자 `2^P` 로 옮겨지고, 거기서 `f(X) = |X|` 는 **정확히 modular** 다:
    `|A∪B| + |A∩B| = |A| + |B|`. Theorem 1 이 그대로 적용된다.
  · **교집합이 곧 반유니피케이션이다.** 경로가 lgg 에 살아남으려면 루트부터 그
    노드까지 심볼이 전부 일치해야 하는데, 그게 정확히 교집합 원소 조건이다.
    별도의 AU 구현 없이 집합 연산으로 같은 것을 얻는다.

### 검증 (`scripts/verify_metric.py` · 실제 Coq 명제 90개)

    ✓ M1 비음수 · M3 대칭성 · M5 유계
    ✓ M2 동일성      d = 0 ⟺ s ≡α t          4,005쌍
    ✓ M4 삼각부등식                           400,000 삼중쌍 전수 0 위반

**M2 가 핵심이다.** `d=0` 이 정확히 α-동치이므로 **`eqx` 가 이 거리의 영집합 그대로**다.
강제성(X1)·`exact` 특징짓기·정규화 불변(X6)이 **전부 보존된다.** 버리는 것이 없다.

### 정직한 관찰

같은 400,000 삼중쌍에서 `1 − F₁` 도 위반이 0이었다. 실제 Coq 명제에서는 Dice 도
metric 처럼 행동한다. 차이는 **보장의 유무**다 — VP-tree·LSH 가지치기는 **한 번의
위반으로도 틀린 답**을 낸다. 인덱싱에는 경험적 운이 아니라 정리가 필요하다.

## 4. PL 쪽 근거 — 세 문헌이 같은 곳으로 수렴한다

| 문헌 | 무엇을 말하나 |
|---|---|
| **path indexing** (McCune, Stickel) | ATP 의 표준 항 인덱싱이 **루트→잎 경로**다 |
| **fingerprint indexing** (Schulz 2012) | *"항의 **비변수 위치 골격은 치환에 불변**"* — 고정 위치에서 표본해 trie 로 |
| **Ramon·Bruynooghe 1998** | Plotkin 의 lgg 가 그 거리 아래 **최소 거리기반 일반화 연산자** |

우리가 격자에서 유도한 표현이 **ATP 가 성능을 위해 독립적으로 도달한 표현**과 같다.
이건 우연이 아니라, 치환에 불변인 골격이 검색의 올바른 단위이기 때문이다.

## 5. 검색 가속 — 실측

Jaccard 는 **집합 유사도**이므로 MinHash 가 정확히 그것을 근사한다.

    P[ minhash_h(A) = minhash_h(B) ] = J(A, B)

서명 `k` 개를 비교하면 표준오차 `1/√k`. 서명을 `b` 개 밴드(행 `r = k/b`)로 쪼개
해시하면, 유사도 `s` 인 쌍이 후보가 될 확률은

    P(s) = 1 − (1 − s^r)^b

`b` 를 키우면 느슨해져 재현율↑·후보↑. `scripts/bench_metric_index.py` 로 실측:

### 후보 5,000개 · 질의 150개 · k=128

    linear 질의당 5.56 ms   (정확, 후보 수에 **비례** — 5만개면 55.6 ms)

     b   r   구축(s)  질의(ms)  후보(중앙)  top10재현  1위일치  선형대비
     8  16    0.03    0.011         2      25.4%    62.7%     499x
    16   8    0.04    0.024         4      39.1%    60.0%     233x
    32   4    0.07    0.314       187      69.1%    68.0%      18x
    64   2    0.12    3.578     3,130      94.7%    96.0%       2x
    128  1    0.18    6.133     4,896      98.3%    99.3%       1x

  · 파싱+경로집합 추출은 **0.05 ms/개** (한 번만 드는 비용)
  · MinHash 단독은 linear 보다 **느리다** — 경로집합이 중앙 19개로 작아서
    `k=128` 서명 비교가 오히려 비싸다. **LSH 의 이득은 서명이 싸서가 아니라
    후보를 줄여서**다.

### 정직한 한계 — 차원의 저주

재현율 95% 를 원하면 `b=64` 인데 후보가 3,130개(전체의 63%)라 이득이 2배뿐이다.
**lemma 쌍의 Jaccard 유사도가 전반적으로 낮아서** LSH 가 잘 갈라지지 않는다.
이것이 [차원의 저주](https://arxiv.org/pdf/0906.0391)의 실제 형태다.

    "metric 이니 무조건 빠르다" 는 성립하지 않는다.

다만 우리 목적은 **정확한 top10 이 아니라 gold 가 프롬프트에 들어가는 것**이고,
그건 더 관대한 조건이다. `b=32`(18배, 후보 187개)로 A 지표가 얼마나 나오는지는
실측해 봐야 안다.

## 7. 실험 결과 (2026-08-22) — **채택하지 않는다**

TEST/VAL 각 n=3000 · `C_RENAME=1`(질의 변수 개명).

| 랭커 | TEST 목표 ALL·P | VAL 목표 ALL·P | **A·P** | C·P | 질의당 |
|---|---|---|---|---|---|
| `tfidf` | 84.2 | 80.8 | 27.7 | 78.2 | 0.03 ms |
| `structural` | 86.7 | 85.1 | 30.8 | 80.7 | 25.7 ms |
| **`eqx`** | **94.9** | 95.2 | **36.4** | 92.0 | **1.9 ms** |
| `jac` | 93.9 | 96.7 | 23.6 | 92.0 | 18.3 ms |
| `jac_eqx` | 94.1 | **96.9** | 23.6 | **92.3** | 18.1 ms |
| `jac_pure` | 90.3 | 89.9 | **8.7** | 89.4 | 15.4 ms |

McNemar 정확검정(TEST, 기준 `eqx`): `jac` +3.03pp (b=182, c=91, p<0.0001) ·
`jac_pure` +19.30pp (b=639, c=60). 전부 유의.

### 왜 기각하는가

**A 지표가 무너진다.** A 는 "cut 없이 gold 를 그대로 쓸 수 있는" 국면이고, 높을수록
안전하다(cut 은 생성 실패·문법 오류 위험이 있다).

    A·P    eqx 36.4  →  jac 23.6 (−12.8pp)  →  jac_pure 8.7 (−27.7pp)
    C·P    eqx 92.0  ≈  jac 92.0            →  jac_pure 89.4

C 는 동등한데 A 만 깎인다. 과거 `auf`·`cov` 가 무너진 것과 **같은 패턴**이다 —
상시 켜진 구조 신호는 일반 goal 에서 노이즈다. `eqx` 의 지시자는 A 국면에서
발화하지 않으므로(성질 S) A 를 해치지 않는다. 그 성질의 값어치가 여기서 다시 확인됐다.

### `jac_pure` 의 실패가 말해 주는 것

    A·P 8.7%   (eqx 의 1/4)

**어휘 정보 없이 구조만으로는 일반 goal 에서 gold 를 못 찾는다.** 구조가 비슷한
lemma 가 너무 많기 때문이다. §6 끝의 "`jac_pure` 가 비슷하면 tfidf·RRF·C' 가 전부
사라진다" 는 기대는 **성립하지 않았다.** tfidf 는 없앨 수 없다.

### 속도 — metric 이 더 느리다

    eqx         1.87 ms      ← 가장 빠름
    jac_pure   15.4 ms
    jac        18.3 ms
    structural 25.7 ms

`eqx` 는 **지시자가 희소해서** 대부분의 후보에서 계산을 건너뛴다. `jac` 은 후보마다
경로집합을 만들어야 한다. "metric 이면 검색이 빨라진다"는 기대는 **여기 규모에서는
반대로 나온다** — LSH 의 이득은 재현율을 크게 포기할 때만 나오고(§5), 우리는
재현율이 곧 목표지표다.

### 남는 값어치

기각은 랭커로서의 기각이고, 이론은 남는다. `d_J = 0 ⟺ α-동치` 이므로 **`eqx` 의
지시자는 이 metric 의 영집합 그대로**다. 즉 `eqx` 를 "진짜 거리의 영집합에서
발화하는 랭커" 로 진술할 수 있고, 강제성·exact 특징짓기·정규화 불변이 전부
metric 언어로 다시 쓰인다. 논문에서는 이 쪽이 쓸모 있다.
