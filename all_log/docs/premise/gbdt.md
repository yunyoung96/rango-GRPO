# GBDT 재랭킹 — 상세 설명

지금까지 시도한 것 중 **가장 크게 오른 방법**이다. 이 문서 하나로 재현할 수 있게 적는다.

| 대상 | RRF 3-way | **GBDT** | 차이 |
|---|---|---|---|
| TRAIN R@50 | 70.6% | **94.1%** | +23.5pp |
| VAL R@50 | 64.8% | **87.7%** | +22.9pp |
| **TEST R@50** | 65.0% | **88.6%** | **+23.6pp** |

TRAIN 에서 배운 트리가 VAL/TEST 에 **그대로 전이**한다(프로젝트가 완전히 다른데도).

> 아직 **실험대에서만** 확인했다. `SparseClient` 에 안 들어갔다 — 지금 학습이 쓰는 값은
> 여전히 순수 TF-IDF 다. 한계는 §9 에 적었다.

## 1. 초등학생용 설명

### 1-1. 무슨 문제인가

수학 문제를 푸는데, 도움이 될 만한 **공식 카드**가 1만 장 있다. 그중 진짜 필요한 카드는
보통 1~2장이다. 1만 장을 다 볼 수는 없으니 **위에서 50장만** 뽑아 주고 싶다.

지금 방식은 "문제에 나온 **단어**가 카드에도 있으면 점수를 준다" 이다. 그런데 문제가
`a + b = b + a` 이면 남는 단어가 `+` 두 개뿐이라, `+` 가 세 개 있는 **엉뚱한 카드**가 1등이
되어 버린다. 단어만 세면 이렇게 된다.

### 1-2. 그래서 어떻게 하나

카드를 볼 때 **여러 명의 심사위원**을 둔다.

    심사위원 1 "단어가 얼마나 겹치나?"          ← 지금 쓰는 방법
    심사위원 2 "식의 모양이 얼마나 닮았나?"
    심사위원 3 "실제로 이 공식을 문제에 끼울 수 있나?"
    심사위원 4 "같은 파일에 있던 공식인가?"
    ...  이렇게 12명

각자 0~1 점을 준다. 문제는 **이 12개 점수를 어떻게 합치느냐** 다.

가장 쉬운 방법은 그냥 더하는 것이다. 하지만 이건 틀린다. 왜냐하면

> "심사위원 2 가 높으면 좋다" 가 **항상** 맞는 게 아니라
> "심사위원 1 도 같이 높을 때만" 좋을 수 있기 때문이다.

이런 **조건부 규칙**은 더하기로는 표현이 안 된다.

### 1-3. GBDT 는 스무고개다

GBDT 는 **스무고개 질문표**를 아주 많이(369개) 만드는 방법이다. 질문표 하나는 이렇게 생겼다.

```
                     심사위원 2 점수가 0.4 보다 큰가?
                        /                      \
                     예                          아니오
                      |                            |
        심사위원 1 이 0.7 보다 큰가?          심사위원 4 가 1.0 인가?
           /            \                      /          \
        예             아니오                 예           아니오
     +2.1점           -0.3점              +0.5점          -1.2점
```

이 표 하나로는 대충만 맞는다. 그래서 **틀린 만큼을 다음 표가 고친다.**

    표 1 을 만든다        →  아직 많이 틀린다
    표 2 는 "표 1 이 틀린 부분" 을 고치도록 만든다
    표 3 은 "표 1+2 가 아직 틀린 부분" 을 고친다
    …  369번 반복

마지막에 369개 표의 점수를 다 더하면 최종 점수다. 이게 **부스팅**(boosting, 밀어올리기)이다.

### 1-4. 왜 잘 되나

더하기 방식(RRF)은 "심사위원 2 는 항상 이만큼 중요" 라고 **한 번에** 정한다.
GBDT 는 "심사위원 1 이 낮을 때는 심사위원 2 를 믿지 마라" 같은 **상황별 규칙**을 배운다.
공식 카드는 종류가 다양해서(등식, 부등식, 목록, 집합…) 상황별 규칙이 훨씬 잘 맞는다.

## 2. 문제 설정 — 정확히 무엇을 랭킹하나

한 증명 스텝마다:

```
입력   goal 상태 (가설 블록 + 목표 명제)
       후보 premise 풀 P = [p_1, …, p_N]      N 은 보통 1만 개 안팎
정답   gold ⊂ P — 그 스텝의 gold tactic 이 실제로 쓴 lemma 들
출력   P 의 순열. gold 가 위에 있을수록 좋다
지표   R@k = gold 중 하나라도 상위 k 안에 든 사례의 비율
```

프롬프트에는 상위 50 개 정도만 들어가므로 **R@50** 이 실질 지표다.

## 3. 특징 12개 — 심사위원들

`scripts/dump_retrieval_features.py` 가 후보마다 뽑는다. 정의는
`scripts/research_structural.py` 에 있다.

| # | 이름 | 무엇을 재나 | 이름 문자열을 쓰나 |
|---|---|---|---|
| 0 | **A' 매칭크기** | premise 를 goal 에 실제로 끼울 수 있나 — **맞물린 부분항의 크기** | ✗ |
| 1 | **B head 일치** | 결론의 최상위 함수가 같은가 (`=` vs `<=`) | 상수만 |
| 2 | **C 연산자 Jaccard** | 쓰인 연산자 집합이 얼마나 겹치나 (`+`,`*`,`::`) | ✗ |
| 3 | **D 모양** | 결론 트리의 노드수·깊이가 비슷한가 | ✗ |
| 4 | **C' 결론 head** | 결론 부분항 head 다중집합의 **IDF 가중 코사인** | 상수만 |
| 5 | **E 가설 매칭** | premise 의 가설이 goal 가설블록에 **이미 있나** | 상수만 |
| 6 | **tfidf** | 현재 rango 점수 (토큰 겹침) | ✓ |
| 7 | **이름 subword** | lemma 이름을 `_`·`.` 로 쪼갠 조각의 tfidf | ✓ |
| 8 | **H 지역성** | 같은 파일 > 같은 디렉토리 > 같은 프로젝트 | ✗ |
| 9 | **G anti-unify** | 두 항의 **최소일반화** 크기 — 트리 위치를 반영 | ✗ |
| 10 | premise 가설 수 | 가설이 많은 lemma 는 적용이 어렵다 (0~8 정규화) | ✗ |
| 11 | 메타변수 비율 | `forall` 변수가 많으면 아무데나 맞는다 (0~10 정규화) | ✗ |

### 3-1. 몇 개만 자세히

**A' 매칭크기** (`sig_match_size`) — 이게 "실제로 쓸 수 있나" 를 재는 신호다.

```
goal      a + b = b + a
premise   forall x y, x + y = y + x

premise 를 **패턴**, goal 을 **고정 항** 으로 두고 x,y 만 대입한다 (Coq 의 apply 와 같은 방향)
   x ← a,  y ← b   →  맞는다
맞물린 부분항의 노드 수 / goal 크기  =  1.0
```

`rewrite` 방향도 본다 — premise 결론이 등식이면 양변 중 하나가 goal 의 **부분항**과
맞는지 확인한다.

**C' 결론 head** (`sig_concl_heads`) — 결론 트리의 모든 부분항 head 를 세어 IDF 코사인.

```
goal      a + b = b + a          heads = {=:1, +:2}
정답      x + y = y + x          heads = {=:1, +:2}
오답      x + (y+z) = x+y+z      heads = {=:1, +:3}
```

TF-IDF 와 다른 점은 **결론에서만** 뽑고 가설부 노이즈가 없다는 것. 그리고 여기 쓰이는
이름은 `length`·`Z.succ` 같은 **전역 상수**라 v8 익명화 대상이 아니다(lemma 이름만 `L#`).

**E 가설 매칭** (`sig_hyp_match`) — `apply X` 는 X 의 가설을 새 subgoal 로 남긴다.
그 가설이 goal 가설블록에 **이미 있으면** 바로 닫히므로 훨씬 유망하다. 결론만 보는
신호들이 통째로 놓치는 축이다.

## 4. 특징 12개 → 벡터 36차원

각 특징을 **세 가지 형태**로 넣는다. 이게 성능의 큰 부분이다.

```python
X[j] = [ F[j][c] / max_c        for c in 0..11 ]   # ① 원시값 (열별 최대로 정규화)
     + [ pct[c][j]              for c in 0..11 ]   # ② 순위 백분위 (0=1등, 1=꼴등)
     + [ 1/(0.15 + pct[c][j])   for c in 0..11 ]   # ③ RRF 변환
```

**왜 세 개인가.**

| 형태 | 무엇을 담나 | 없으면 |
|---|---|---|
| ① 원시값 | 절대 크기 — "C' 가 0.9 다" | 임계값 규칙을 못 만든다 |
| ② 순위 백분위 | **이 사례 안에서의 상대 위치** | 사례마다 점수 스케일이 달라 비교 불가 |
| ③ RRF 변환 | 상위권을 **강하게 확대** — 1등과 10등의 차이를 크게 | 상위권 미세 구분을 못 한다 |

②가 핵심이다. 어떤 증명 지점은 후보가 500개고 어떤 곳은 1만 개다. 원시 tfidf 0.08 이
어느 곳에선 1등이고 다른 곳에선 300등이다. **백분위로 바꾸면 사례들이 같은 자로 재진다.**

③은 `RRF_K = 0.15` 다. 백분위가 0(1등)이면 `1/0.15 = 6.67`, 0.1(상위10%)이면 `1/0.25 = 4.0`.
상위권에서 값이 급격히 벌어진다 — 트리가 "아주 위쪽" 을 따로 다루기 쉬워진다.

## 5. 왜 비선형이어야 하나

선형 학습(§10.3)은 **큰 셋에서 개선 0** 이었다. 이유가 분명하다.

RRF 자체가 `1/(k+순위)` 들의 **합**이다. 그런데 우리는 그 변환값(③)을 특징으로 넣어 준다.
그러면 선형 모델이 배울 수 있는 최선은 그 특징들에 가중치를 붙이는 것 — 즉 **RRF 를
재현**하는 것이다. 넘어설 수가 없다.

넘어서려면 **상호작용**이 필요하다.

```
"C' 가 높으면 좋다"                    ← 선형으로 표현됨
"C' 가 높은데 tfidf 도 높으면 특히 좋다"  ← 곱셈. 선형으로 표현 안 됨
"메타변수가 아주 많으면 A' 는 믿지 마라"   ← 조건부. 선형으로 표현 안 됨
```

두 번째 예가 실제로 중요하다. 메타변수가 10개인 lemma(`forall a b c d …`)는 **아무 goal
에나 맞는다** — A' 가 1.0 이어도 정보가 없다. 트리는 "메타변수 비율 > 0.7 이면 A' 가지를
타지 마라" 를 배울 수 있다. 선형은 A' 에 하나의 가중치만 줄 수 있다.

## 6. GBDT 알고리즘 — 안에서 무슨 일이

`HistGradientBoostingClassifier` (sklearn) 를 쓴다. 순서대로 적는다.

### 6-1. 히스토그램 구간화 (Hist)

학습 전에 **각 특징을 255개 구간으로 나눈다**. 연속값 `0.4173` 대신 구간 번호 `107` 로 본다.

    왜:  분할점 후보를 찾을 때 정렬된 전체 값을 훑으면 O(n log n) 이다.
         구간으로 바꾸면 히스토그램 255칸만 훑으면 되어 O(255) 다.
         16만 표본 × 36특징 × 369트리 라 이 차이가 결정적이다.

정확도 손실은 거의 없다 — 랭킹에 0.4173 과 0.4180 의 차이는 의미 없다.

### 6-2. 초기 예측

전체 positive 비율 `p0 = 6604/166604 ≈ 0.0396` 의 **로그오즈**로 시작한다.

    F_0(x) = log(p0 / (1 - p0)) = log(0.0396/0.9604) ≈ -3.19      (모든 x 에 동일)

### 6-3. 매 반복 — 기울기를 배운다

손실은 **이진 로그손실**이다. `p = sigmoid(F(x))` 일 때

    L = -[ y·log(p) + (1-y)·log(1-p) ]

여기서 각 표본의 1차·2차 미분이 아주 단순해진다.

    g_i = ∂L/∂F = p_i - y_i          ← "얼마나 틀렸나" (부호 포함)
    h_i = ∂²L/∂F² = p_i (1 - p_i)    ← "얼마나 확신하나"

**다음 트리는 y 가 아니라 g 를 맞추도록 학습한다.** 이미 잘 맞춘 표본은 `g ≈ 0` 이라
새 트리가 신경 쓰지 않는다 — 자동으로 **틀린 것에 집중**한다.

### 6-4. 분할점 고르기

노드를 왼쪽/오른쪽으로 가를 때 이득(gain)을 이렇게 잰다.

    G = Σg,  H = Σh  (그 노드의 표본들)
    gain = ½ [ G_L²/(H_L + λ) + G_R²/(H_R + λ) − G²/(H + λ) ]      λ = l2_regularization = 1.0

36개 특징 × 255구간을 전부 훑어 gain 이 최대인 (특징, 구간)을 고른다.
`max_depth=6` 까지, 잎마다 최소 `min_samples_leaf=40` 개를 유지한다.

### 6-5. 잎 값

    w = − G / (H + λ)

그리고 **학습률로 줄여서** 더한다.

    F_{m}(x) = F_{m-1}(x) + 0.06 × w(x)

한 번에 다 고치지 않고 조금씩(6%) 고친다. 이게 **shrinkage** 이고, 과적합을 크게 줄인다.
대신 트리가 많이 필요하다 — 그래서 369개다.

### 6-6. 조기 종료

`validation_fraction=0.15` 로 학습표본의 15%를 떼어 검증에 쓴다. 검증 손실이 더 이상
줄지 않으면 멈춘다. `max_iter=400` 을 걸었는데 **369에서 멈췄다** — 400을 다 쓰지 않았으니
트리 수가 부족해서 성능이 낮은 것은 아니라는 뜻이다.

### 6-7. 예측 → 랭킹

    score(p_j) = sigmoid( F_369(x_j) ) = "이 후보가 gold 일 확률"

한 사례 안의 후보들을 이 확률 내림차순으로 정렬한다. 확률의 **절대값**은 안 쓴다 —
같은 사례 안의 **상대 순서**만 쓴다.

## 7. 모의 코드

### 7-1. 전체 파이프라인

```
# ── 준비 (한 번) ────────────────────────────────────────────────
학습사례 = []
for 증명스텝 in TRAIN:
    풀   = 그 시점까지 보인 premise 전부, 필터 통과분          # 보통 1만 개
    gold = 그 스텝의 gold tactic 이 쓴 lemma 들
    if gold 없음: 건너뜀

    tf = TFIDF(goal, 풀)
    후보 = tf 상위 400개  ∪  gold                            # gold 는 무조건 포함
    for j in 후보:
        F[j] = [A'(j), B(j), C(j), D(j), C'(j), E(j),
                tf[j], 이름subword(j), H(j), G(j), 가설수(j), 메타변수비(j)]
    학습사례.append( (F, gold 의 인덱스들) )

# ── 특징 벡터 만들기 ────────────────────────────────────────────
for (F, gold) in 학습사례:
    for c in 0..11:
        열 = [F[j][c] for j in 후보]
        pct[c] = 순위백분위(열)                # 0.0 = 1등, 1.0 = 꼴등
        mx[c]  = max(|열|)  or  1.0
    X[j] = [F[j][c]/mx[c] for c] + [pct[c][j] for c] + [1/(0.15+pct[c][j]) for c]

# ── 학습 표본 (불균형 처리) ─────────────────────────────────────
Xs, ys = [], []
for (X, gold) in 학습사례:
    뽑기 = gold 전부  +  gold 아닌 것 중 무작위 40개          # 1:40 다운샘플
    for j in 뽑기:
        Xs.append(X[j]);  ys.append(1 if j in gold else 0)

# ── 학습 ────────────────────────────────────────────────────────
모델 = GBDT(트리400, 학습률0.06, 깊이6, 잎최소40, L2=1.0, 조기종료)
모델.fit(Xs, ys)

# ── 사용 ────────────────────────────────────────────────────────
def 랭킹(goal, 풀):
    tf   = TFIDF(goal, 풀)
    후보 = tf 상위 400개
    X    = 특징벡터(goal, 후보)
    확률 = 모델.predict_proba(X)[:, 1]
    return 후보를 확률 내림차순 정렬  +  나머지는 tf 순서 그대로
```

### 7-2. GBDT 내부 (부스팅 루프)

```
구간표 = 각 특징을 255구간으로 나눈 경계값          # 히스토그램 준비

F = [log(p0/(1-p0))] * n                        # 모든 표본 동일한 초기값
for m in 1..400:
    p = sigmoid(F)
    g = p - y                                   # 1차 미분: 틀린 정도
    h = p * (1 - p)                             # 2차 미분: 확신 정도

    트리 = 빈 트리
    노드큐 = [뿌리(모든 표본)]
    while 노드큐 있고 깊이 < 6:
        노드 = 노드큐.pop()
        최선 = None
        for c in 0..35:                          # 36개 특징
            히스토그램 = [(Σg, Σh, 개수)] * 255   # 구간별로 누적
            for 경계 in 1..254:
                G_L,H_L = 경계 왼쪽 누적
                G_R,H_R = 전체 - 왼쪽
                if 왼쪽개수 < 40 or 오른쪽개수 < 40: 건너뜀
                gain = ½[ G_L²/(H_L+1) + G_R²/(H_R+1) − G²/(H+1) ]
                최선 = max(최선, (gain, c, 경계))
        if 최선 없음 or gain <= 0:
            노드를 잎으로: w = −Σg / (Σh + 1)
        else:
            노드를 (c, 경계) 로 가르고 자식 둘을 큐에 넣는다

    F += 0.06 * 트리.예측(X)                     # shrinkage
    if 검증손실이 개선 안 됨(연속 n_iter_no_change): break
```

| | RRF 이름없이 | 45.3% | 57.7% | 71.4% |

읽는 법:

**① 전이가 된다.** TRAIN 에서 배운 트리가 VAL/TEST 에 +23pp 를 그대로 낸다. VAL/TEST 는
프로젝트가 완전히 다르다(TEST 에는 CompCert 가 있다). 개선폭이 세 스플릿에서 거의 같다는

**② 이름을 안 써도 된다.** "RRF 이름없이" 가 "RRF 3-way" 보다 오히려 조금 높다. lemma
이름 신호는 사실상 불필요하다 — v8 익명화와 충돌하지 않는다.

**③ 가장 큰 이득은 상위권이다.** R@10 이 37% → 71% 로 거의 두 배다. 프롬프트에 50개를
넣는다면 R@50 이 중요하지만, 10개만 넣는 압축 설정에서는 이득이 훨씬 크다.
