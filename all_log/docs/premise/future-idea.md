## ① 파서 recall 개선 ★ 가장 큰 지렛대

**증상**: 적용가능 판정의 **gold recall 이 46~50%** 다. `decompose`/`parse` 가
notation·mathcomp 표기에서 실패하면 그 premise 는 구조 신호가 **전부 0** 이 된다.

**왜 중요한가**: C'(결론구조) · eq(트리일치) · 적용가능 — **세 신호가 같은 파서를 쓴다.**
파서를 고치면 셋이 동시에 좋아진다. 지금 `eq` 가 C 에서만 통하고 A 에서 무해에 그치는 것,
적용가능을 필터로 못 쓰는 것(§16 에서 R@50 −9pp)이 전부 여기서 온다.

**할 일**
  · 파싱 실패 premise 를 유형별로 모은다 (어떤 notation 이 얼마나?)
  · 상위 몇 개 유형만 처리해도 recall 이 얼마나 오르는지 본다
  · `Set Printing All` 로 얻은 형태를 파서에 넣는 경로도 검토 (notation 이 펴진다)

## ② head 역인덱스로 후보 확장 ★ 상한을 통째로 올린다

**증상**: 후보가 **tfidf 상위 N** 에서만 온다. gold 가 tfidf 5000위면 재랭킹이 손댈 수 없다.

```
gold 전부가 tfidf 상위  400 안   56.7%
gold 전부가 tfidf 상위 2000 안   74.3%   ← 나머지 25.7% 는 원리적으로 못 잡는다
```

**아이디어**: 결론 **head 심볼**로 역인덱스를 만들어 후보를 합친다. goal 결론 head 가
`le` 면 결론이 `le …` 인 premise 를 tfidf 순위와 무관하게 후보에 넣는다.

    후보 = tfidf 상위 N  ∪  head 인덱스[goal 결론 head]

head 인덱스가 작으면 비용이 거의 없고 상한이 통째로 올라간다. 크면 head+두번째 심볼로
좁힌다. `scripts/headroom.py` 가 크기와 gold 포함률을 잰다.

## ③ 가설부 매칭(E) 신호 추가

`sig_hyp_match` — lemma 의 **가설**이 goal 문맥에 이미 있는가. `apply X` 는 X 의 가설을
새 subgoal 로 남기는데, 이미 있으면 바로 닫히므로 훨씬 유망하다.

**GBDT 특징(12개)에는 들어 있지만 `eqcov` 에는 빠져 있다.** RRF 네 번째 항으로 넣어
A 를 해치지 않는지 확인한다. 구현은 이미 `tier_rank.sig_hyp_match` 에 있다.

## ④ 다중 lemma 다양성 재랭킹

**증상**: TEST R@50 54.6% vs ALL@50 45.4% — **9.2pp 를 다중 lemma 스텝에서 잃는다.**
lemma 2개 이상 필요한 스텝이 23.7% 이므로, 그중 약 40% 가 부분적으로만 잡힌다.

**원인 가설**: 한 번 정렬해 상위 k 를 자르면, 두 lemma 의 성격이 다를 때
(하나는 rewrite 용 등식, 하나는 apply 용 함의) 비슷한 것들이 상위를 채워 두 번째가 밀린다.

**아이디어**: MMR — 하나 고르면 그와 **너무 비슷한 것을 감점**한다. 유사도는 결론 head
다중집합 코사인을 재활용한다(이미 계산돼 있다).

## ⑤ 부분항별 다중 질의

`rewrite L` 은 L 이 goal 의 **부분항**에 맞는다. 지금은 결론 **전체**로 한 번만 질의한다.

**아이디어**: goal 결론의 부분항마다 질의를 만들어 RRF 로 합친다.
`src/tactic_gen/search_query.py` 에 추상화 사다리(depth 3→2→4→1)를 만들어뒀는데
**아직 쓰지 않고 있다.**

주의: 질의가 늘면 비용이 선형으로 늘고, 흔한 부분항(`nat`, `true`)은 노이즈만 만든다
→ IDF 가 낮은 부분항은 건너뛴다.

## ⑥ Definition 특별 처리

gold 가 `Definition` 이면 "결론" 이 명제가 아니라 **본문**이라 C'·eq 가 무의미하다.

```
gold   Definition ulp x := match Req_bool x 0 with | true => … end.
질의   match Req_bool x 0 with …          ← 명제가 아니다
```

`unfold`·`rewrite` 로 정의를 쓰는 경우다. **정의된 이름이 goal 에 나타나는가**로 잡아야
한다. 먼저 gold 중 Definition 비중을 재고(`headroom.py` ⑤), 크면 별도 신호를 만든다.

## ⑦ 증명 동시출현 사전확률

"이 goal 의 상수를 쓰는 **이전 증명들**이 자주 쓴 lemma" — 학습 없이 **카운트만**으로
만드는 사전확률. rango 에 proof retrieval 이 이미 있어 재료가 있다.

지역성 신호 H 가 단독으로는 약했지만(R@50 26.6%) RRF 에 넣으니 **이름 신호를 대체**했다
(§10.5b). 이것도 단독으로는 약해도 조합에서 값이 있을 수 있다.

**주의**: 같은 파일·프로젝트 안에서만 세야 한다. 전역 통계는 프로젝트 전이를 깬다.

## ⑧ contrastive 재시도 — 우선순위 낮음

### 지금까지의 결과

**분모: gold 가 후보 풀에 있는 TEST 스텝 40건 (예비)**

| 랭커 | 목표지표 ALL@50 |
|---|---|
| rrf / eq | **95.0%** |
| ctr (RRF 융합) | 91.8% |

**RRF 에 얹어도 아무것도 더하지 못한다.** 학습 당시 지표는 좋아 보였다 —

```
epoch 13: 재랭킹 top1 7.0% top5 21.6% top10 36.9%
          (tfidf 원본  3.1%      11.2%      17.0%)
```

top10 이 두 배지만, **tfidf 는 이미 RRF 에 크게 뒤지는 약한 기준선**이었다.

### 왜 안 되나 — 진단

| 의심 | 근거 |
|---|---|
| 손실 정체 | 12~13 epoch 내내 2.89~2.90 |
| **정보 중복** | RRF 의 C' 도 구조 신호다. 익명 구조 n-gram(F)·anti-unification(G) 도 RRF 에 넣으면 개선 0 이었다 |
| 표현이 거칠다 | 57토큰 익명화가 깊은 중첩을 `max_len=192` 에서 자른다 |
| negative 가 쉽다 | hard negative 를 **tfidf 상위**에서 뽑았다 — 기준선이 RRF 인데 |

### 재시도한다면

1. **negative 를 RRF(또는 eqcov) 상위로** — 지금 기준선에서 뽑아야 진짜 hard 다
2. **`eq` 신호를 입력 특징으로 주입** — 트리 완전일치를 모델이 직접 보게
3. 손실 정체 해소 — 학습률 스케줄, 층/차원 확대, `max_len` 확대
4. **큰 표본으로 전이 재측정** — 지금 40건은 결론을 내기에 부족하다

### 다만

`eqcov` 가 **학습 없이** 목표지표 95%대를 낸다. contrastive 가 이기려면 그보다 나아야
하는데, 위 진단대로면 **정보가 중복**이라 크게 기대하기 어렵다.
①~④ 를 먼저 하고, 그래도 남는 손실이 구조적이면 그때 돌아온다.

## ⑨ `NORMALIZE_RATE` — 근거 없이 0.5 다

### 지금 상태

`normalize_names.should_normalize` 의 주석이 근거다.

> 전부 정규화하면 테스트(실제 이름)와 분포가 어긋난다. 섞어야 모델이 메커니즘을 배우고
> 실제 이름에도 적용한다.

**그런데 ablation 이 없다.** 0.5 를 고른 측정 근거가 문서 어디에도 없다.

### 양쪽 논리

| rate | 근거 |
|---|---|
| 낮게 (0.5) | 추론은 진짜 이름이므로 분포를 맞춘다. 진짜 이름에는 **의미 힌트**가 있다(`add_comm` → 교환법칙) |
| 높게 (1.0) | 절반이 진짜 이름이면 모델은 **그 절반에서 여전히 외울 수 있다**. 암기 경로가 남으면 읽는 능력을 안 기른다 |

### 왜 높여도 될 가능성이 있나

정규화는 **일관된 개명**이다 — 프롬프트와 정답에 같은 매핑을 쓴다. 실측(익명화 손실 검사,
TRAIN 400건)에서 읽기 가능성이 **소수점까지 동일**했다.

| | 익명화 OFF | 익명화 ON |
|---|---|---|
| 정답 식별자가 프롬프트에 있음 | 80.8% | **80.8%** |
| 어디에도 없음(환각) | 7.7% | **7.7%** |

즉 모델이 배우는 것은 "프롬프트에서 이름을 찾아 베껴라"이고, 그 능력은 이름이 `L0` 든
`Nat.add_comm` 든 그대로 전이된다. 분포 불일치 우려는 **표면 형태**에 대한 것이지
능력에 대한 것이 아닐 수 있다.

### 어떻게 잴 것인가

`NORMALIZE_RATE` 0.5 / 0.8 / 1.0 으로 각각 학습해 rand200 성공률 비교.

★ **순서 주의**: cut 을 먼저 넣어야 한다. cut 이 들어가면 "프롬프트에 없는 이름을 쓰는
15.2%" 가 줄어들어 **정규화의 부작용 자체가 달라진다.** cut 없는 상태에서 rate 를 재면
그 결과가 cut 도입 후에 뒤집힐 수 있다.

## ⑩ 추론에서 정규화를 켜려면 **역매핑이 필요하다** (지금 없다)

| 경로 | 정규화 |
|---|---|
| 학습 `collate` | ✅ 적용 (rate 만큼) |
| 추론 `collate_input` | ❌ **안 함** |
| 역매핑 코드 | ❌ **없음** |

지금은 추론에서 정규화를 안 하므로 되돌릴 것이 없다 — 모델이 진짜 이름을 보고 진짜
이름을 생성하고 Coq 이 그대로 실행한다.

**★ 위험**: 학습과 형태를 맞추려고 추론 정규화를 켜면, 모델이 `apply L0.` 를 생성하고
Coq 은 `L0` 를 모른다. 켜기 전에 **반드시 역매핑을 구현**해야 한다
(`mapping` 을 저장해 두고 생성된 tactic 에 역방향 치환).

## ⑪ ★ built-in(stdlib)은 익명화도 [TYPES] 주입도 하지 말 것 — **구현 예정**

### 왜

익명화의 목적은 "**그 프로젝트에만 통하는 이름**을 외워서 찍는 습관"을 끊는 것이다.

| lemma | 외우면 | 익명화하면 |
|---|---|---|
| `gpaco5_unfold` (프로젝트 전용) | 그 프로젝트에만 통함 | **이득** — 끊는 게 맞다 |
| `Nat.add_comm` (stdlib) | **어느 프로젝트에서나 통함 = 진짜 지식** | **손해** |

사전학습 모델은 이미 `Nat.add_comm : forall n m, n+m = m+n` 을 안다.
`L0` 으로 바꾸면 **그 지식을 못 쓰게 막는 셈**이다.

`[TYPES]` 주입도 마찬가지다. `Inductive list A := nil | cons` 를 프롬프트에 넣는 것은
토큰 낭비다 — 모델이 이미 안다. 그 토큰으로 premise 를 더 넣는 편이 낫다.

### 지금 코드는 어떻게 되어 있나

`normalize_names.renameable()` 에 **원칙은 이미 있다**.

```python
def renameable(name):
    if name in _PROTECTED: return False          # nat, bool, list, S, O, nil, cons ...
    slot = _index().get(name)
    return any(k != "stdlib" for k in slot)      # ★ stdlib 전용 이름은 제외
```

**그런데 premise lemma 이름에는 이 검사가 안 걸린다.**

```python
# build_mapping 안
# ★ renameable() 을 쓰면 안 된다 — 정의 인덱스(func_defs)에 있는 이름만 허용하는데
#   premise 는 lemma 라 인덱스에 없다(실측 235건 중 134건이 걸려 치환 0).
if pn not in _PROTECTED and pn not in _HEADERS and len(pn) > 1:
    prem_names.append(pn)
```

`_PROTECTED` 에는 `nat`·`S`·`nil` 같은 **타입·생성자**만 있고 `Nat.add_comm`·`app_assoc`
같은 **lemma 이름**은 없다 → **stdlib lemma 도 `L0` 이 된다.**

### 어떻게 고치나

premise 는 `Sentence` 객체라 **출처 파일 경로**를 안다. 이름 인덱스가 아니라 **경로로**
판정하면 위 문제가 없다.

```python
_STD_PATH = re.compile(r"(coq/theories|/stdlib/|/Coq/|theories/(Init|Lists|Arith|ZArith|"
                       r"NArith|Bool|Logic|Reals|QArith|Sets|Relations|Classes|Numbers|"
                       r"Strings|Sorting|Structures|Program|Wellfounded|FSets|MSets)/)", re.I)

def is_stdlib(premise) -> bool:
    return bool(_STD_PATH.search(getattr(premise, "file_path", "") or ""))
```

  1. `build_mapping(premises=...)` 이 `Sentence` 를 받아 `is_stdlib` 인 것은 `prem_names`
     에서 제외 (지금은 텍스트만 받아 경로를 모른다 — 시그니처 변경 필요)
  2. `augment.selective_types` 가 stdlib 타입을 `[TYPES]` 에서 제외
  3. 환경변수로 켜고 끌 수 있게: `NORMALIZE_SKIP_STDLIB=1` · `INJECT_SKIP_STDLIB=1`

### 기대 효과

  · stdlib gold 는 이름이 살아남아 **사전학습 지식을 쓸 수 있다**
  · `[TYPES]` 에서 stdlib 타입이 빠져 **토큰이 절약**된다 → premise 를 더 넣는다
  · 프로젝트 전용 이름은 그대로 익명화 → 암기 차단 목적은 유지

### 측정

`scripts/stdlib_share.py` — 후보 풀·gold 중 stdlib 비중.
비중이 크면 효과가 크고, 작아도 **해가 없는 변경**이다(진짜 지식을 막지 않는 것뿐).

## ⑫ conjecture 로 "lemma 쓰는 법" 학습 데이터 늘리기

### 왜 — lemma 를 쓰는 tactic 이 15.2% 뿐이다

TRAIN 5,000 스텝 실측:

| 분류 | 비율 |
|---|---|
| 전역 이름 **없음** (`intros`·`Proof`·`Qed`·`reflexivity` …) | **77.3%** |
| 전역 이름 있음 | 22.7% |
| **└ ★ lemma(명제) 사용** | **15.2%** |
| └ 함수만 (`unfold f`, `destruct (f x)`) | 4.7% |
| └ 타입·생성자만 | 1.7% |
| └ 사전에 없는 이름 (지역 가설 오추출) | 1.1% |

tactic head 별로 보면 lemma 사용은 세 계열에 몰려 있다.

```
apply    전체의 10.6%  ·  그중 lemma 사용 51.9%
rewrite  전체의  6.7%  ·  그중 lemma 사용 45.5%
move     전체의  1.8%  ·  그중 lemma 사용 48.3%
Proof + Qed 만 17%     ·  lemma 사용 0%
```

**우리가 공들인 것(structural 검색 · cut · 정규화)은 전부 이 15.2% 에만 작용한다.**
그런데 v8 분석에서 **실패의 44%가 `rewrite`/`apply`** 였다 — 전체의 15%가 실패의 44%다.
즉 **가장 중요한 부분의 학습 신호가 가장 적다.**

→ 이 15.2% 를 **인위적으로 늘릴 수 있는가**가 이 아이디어다.

### 무엇을 하나 — conjecture = 합성한 명제

기존 증명에서 자연히 나오는 lemma 사용 예제 외에, **명제를 합성해** 추가 예제를 만든다.

#### (가) cut 의 **하위 goal** 을 별도 예제로 — 비용 0, 즉시 가능

지금 cut 은 한 덩어리다.

```
assert (P) as H_asrt0. { exact L. }
eapply H_asrt0.
```

`assert (P)` 직후의 goal 은 **정확히 `P` 이고 가설은 그대로**다 — Coq 없이 합성할 수 있다.
그 상태를 새 예제로 만들면:

```
[STATE]   goal: P            (가설은 원래 것 그대로)
[PREMISES] … P 로 재검색한 결과 → L 이 확실히 들어온다
[TACTIC]  exact L.
```

**"명제를 세우는 법"과 "세운 명제를 푸는 법"을 나눠서** 가르치게 된다.
추론에서 탐색이 하위 goal 을 따로 푸는 구조와도 맞는다.

현재 cut 이 **4,648개**이므로 그만큼의 예제가 공짜로 생긴다.

#### (나) 검색 성공 스텝에도 cut 을 씌우기

지금은 gold 가 프롬프트에 **없을 때만** cut 을 만든다. 있을 때도 만들면:

```
원본   apply L.                         (L 이 프롬프트에 있음)
추가   assert (P) as H. { exact L. }    ← "명제를 세우는 법" 예제
       apply H.
```

① 판정 스텝이 4,973개이므로 그만큼 더 생긴다.
**단, 원본과 합성본 중 무엇을 정답으로 볼지가 애매해진다** — 둘 다 맞다.
증강(augmentation)으로 섞어 넣되 비율을 조절해야 한다.

#### (다) lemma 를 goal 로 되돌리는 역방향 합성 — Coq 필요

프로젝트의 lemma `L : H1 -> H2 -> C` 에 대해:

```
[STATE]   가설: H1, H2        goal: C
[TACTIC]  apply L.
```

이런 예제를 **lemma 마다** 만들 수 있다. 프로젝트 lemma 수만큼 무제한에 가깝다.

**위험 두 가지.**
- `exact L` 로 바로 닫히는 **너무 쉬운** 예제가 되기 쉽다 — 배울 게 없다
- 합성 goal 이 실제 증명 상태와 **분포가 다르다**(가설이 정확히 L 의 전제뿐)

→ 인자를 일부 인스턴스화하거나 결론을 부분적으로 변형해 난이도를 만들어야 하고,
  그러면 **Coq 으로 `apply L` 이 실제로 닫는지 검증**해야 한다.

#### (라) 기존 증명의 중간 상태 + 다른 lemma — Coq 필요

같은 goal 을 닫는 **다른 lemma** 가 있으면 그것도 정답이다.
후보 lemma 를 골라 Coq 으로 검증하면 **같은 상태에 여러 정답**을 얻는다.
`apply` 계열의 다양성이 늘어난다.

### 순서와 비용

| 안 | Coq 필요 | 추가 예제(추정) | 위험 |
|---|---|---|---|
| **(가) cut 하위 goal** | ❌ | 약 4,600 | 낮음 — 상태가 정확히 유도됨 |
| (나) 검색 성공에도 cut | ❌ | 약 5,000 | 중 — 정답이 둘이 됨 |
| (다) 역방향 합성 | ✅ | 매우 많음 | 높음 — 분포 차이·난이도 |
| (라) 대체 lemma 발굴 | ✅ | 중간 | 중 |

**(가)부터 한다.** Coq 이 필요 없고, 상태가 `assert` 의 의미로 정확히 결정되며,
지금 cut 파일에 이미 명제 `P` 가 들어 있어 **추가 계산이 거의 없다.**

(다)(라)는 Coq + 빌드된 프로젝트가 있어야 하는데 이 머신에는 원본 `.v` 가 없다
([speed.md §1-1](speed.md) · [repair.md §6](repair.md)). Vast.ai 이관 시에도 마찬가지다.

### ★ 무엇으로 판정할 것인가

**데이터가 늘었다는 것 자체는 성과가 아니다.** ⑬(전이 갭)으로 재야 한다.

```
평가 A: 학습에서 본 프로젝트의 held-out 파일
평가 B: 학습에서 안 본 프로젝트
전이 갭 = A − B
```

증강 전/후로 이 갭을 비교한다. 갭이 안 줄면 **쉬운 예제만 늘린 것**이다.

> 이 프로젝트에서 작은 표본만 보고 "된다"고 판단했다가 뒤집힌 적이 네 번 있다.
> (가)조차 **먼저 소규모로 만들어 갭을 재고** 전면 적용한다.

## ⑬ ★ 전이 갭 직접 측정 — 1순위

지금 지표는 전부 **검색 지표**(gold 가 프롬프트에 들어갔나)다.
연구 목표는 **"읽어야만 풀 수 있게 만들어 미지 프로젝트로 전이"** 인데,
**전이 자체를 한 번도 재지 않았다.**

```
평가 A: 학습에서 본 프로젝트의 held-out 파일   ← 프로젝트 내 일반화
평가 B: 학습에서 안 본 프로젝트                ← 프로젝트 간 전이
전이 갭 = A − B          ← 이게 줄어드는 것이 목표 달성이다
```

이걸 갖추면 처음으로 답할 수 있는 질문들:

| 질문 | 비교 |
|---|---|
| 정규화가 전이를 돕는가 | `NORMALIZE_RATE` 0 vs 0.5 vs 1.0 의 갭 |
| `[TYPES]`/`[DEFS]` 주입이 돕는가 | `INJECT_*` ON/OFF 의 갭 |
| cut 이 돕는가 | `CUTS_PATH` ON/OFF 의 갭 |
| 증강(⑫)이 돕는가 | 증강 전/후의 갭 |

지금은 CompCert 한 점만 있어 갭을 볼 수 없다.
**⑫를 포함한 모든 아이디어의 판정 근거가 여기 달려 있으므로 이것이 1순위다.**

주의: 평가에서 `NORMALIZE_INFERENCE=1` 을 켜야 한다(⑩). 안 켜면
학습(전부 정규화)과 추론(원래 이름)이 어긋나 갭이 과대평가된다.

## ⑭ `DISTRACTORS` 되살리기

`[PREMISES]` 에 **이름은 그럴듯한데 명제가 다른** lemma 를 k 개 섞는다.
이름으로 찍으면 틀리고 **명제를 읽어야** 맞는다.

이미 구현돼 있다(`DISTRACTORS=k`). v8 에서 "변수를 하나라도 줄여 **정규화 효과만
깨끗이** 보려고" 껐다. 정규화 효과를 확인한 지금은 되살릴 때다.

⑫와 겹치는 부분: ⑫가 **양**을 늘린다면 ⑭는 **압력**을 높인다. 둘 다 ⑬으로 판정한다.

## ⑮ 검색 설계를 다시 — `EQ_W = 3.0` 을 없애는 길

### 지금이 왜 못생겼나

```python
EQ_W = 3.0   # 트리 완전일치 가산. RRF 한 항의 최대(1/60)보다 훨씬 커야 한다
점수 = RRF(tfidf순위, 결론머리IDF순위, 질의포함률순위) + EQ_W × [결론트리 == goal트리]
```

문제가 셋이다.

1. **손으로 정한 상수 하나가 나머지를 압도한다.** RRF 항의 최대 기여가 1/60 ≈ 0.017 인데
   가산이 3.0 이다. 사실상 "트리가 같으면 무조건 1위, 아니면 tfidf" 인 2단 규칙이다.
2. **전부 아니면 전무다.** 결론 트리가 *글자 그대로* 같아야 한다. 인자 하나만 달라도 0점이다.
   그래서 A(일반 goal)에서는 오히려 **방해**가 되고(실측: rrf 가 A 에서 더 낫다),
   C(cut 후 재검색)에서만 크게 이긴다 — 그때는 질의가 곧 그 명제라 당연히 일치한다.
3. **`rewrite` 에는 애초에 틀린 질문이다.** `rewrite L` 은 L 의 등식 **한쪽이 goal 의
   부분항**과 맞아야 하는데, 우리는 *결론 전체가 goal 과 같은지*를 본다.
   lemma 를 쓰는 tactic 의 45.5% 가 `rewrite` 다.

즉 지금 구조는 **cut 경로를 되게 만들려고 끼워 넣은 특례**에 가깝다. 아래는 그걸
제대로 된 신호로 바꾸는 안들이다.

---

### ⑮-0 ★ 먼저 알아야 할 것 — 단방향 매칭은 **이미 시도했고 무너졌다**

`tier_rank.py` 최종 랭커 주석에 기록이 있다.

> 트리 완전일치는 일반 goal 에서 거의 발화하지 않아 **무해**하고, assert 하위목표
> (goal 이 곧 lemma 문장)에서는 정확히 그 질문이라 강력하다.
> **단방향 매칭까지 넣으면 일반 goal 이 무너진다(ALL@50 45.4% → 18.2%)**
> — 그래서 완전일치만 쓴다.

즉 `EQ_W = 3.0` 은 게을러서 고른 게 아니라 **후퇴한 결과**다.
아래 안들은 그 실패를 되풀이하지 않는 형태여야 한다.

**왜 무너졌나(가설).** 단방향 매칭은 사실상 이진이고 **너무 관대**하다.
`forall A (x:A), P x` 처럼 일반적인 lemma 는 거의 모든 goal 에 매칭된다.
거기에 큰 가산을 주면 **무관한 것이 1위**가 되어 전부 뒤집힌다.

**그래서 필요한 성질**: "맞는가" 가 아니라 **"얼마나 딱 맞는가"** 를 재야 하고,
**너무 일반적인 것에는 벌점**이 붙어야 한다.

---

### ⑮-A ★ α-동치를 0 으로 두는 **거리 함수** — 포섭 격자에서 유도

#### 바탕 구조: 포섭 격자

항을 α-동치로 나눈 집합에 **포섭 순서**를 준다.

```
s ⊑ t   ⟺   ∃σ. σ(s) = t          "s 가 t 보다 일반적이다"
```

이 순서에서 **반유니피케이션**(anti-unification, Plotkin·Reynolds 1970)이 정확히 **만남(meet)** 이다.

```
t₁ ⊓ t₂  =  최소 일반화(lgg)  =  둘을 모두 인스턴스로 갖는 가장 구체적인 항
```

1차 항에서는 α 차이를 빼고 **유일하게 존재**하며, 유니피케이션이 이음(join)이다.
즉 우리가 다루는 대상이 **격자**다 — 거리를 손으로 만들지 말고 여기서 유도한다.

#### 값매김에서 거리 뽑기

`size(t)` = **고정 기호 출현 수**(메타변수는 세지 않는다). 포섭에 대해 단조다.

```
s ⊑ t  ⟹  size(s) ≤ size(t)
```

격자에 단조 값매김이 있으면 표준적으로 다음이 나온다(집합의 `|A|+|B|-2|A∩B|` 와 같은 꼴).

```
d(t₁, t₂) = size(t₁) + size(t₂) − 2·size(t₁ ⊓ t₂)
```

**`d = 0 ⟺ t₁ ≡α t₂`.** α-동치면 lgg 가 그 항 자신이라 서로를 완전히 설명한다.
원하던 성질이 정의에서 바로 따라 나온다.

#### 검색은 비대칭이다 — 잔차를 둘로 가른다

`apply L` 이 되려면 **goal 이 L 결론의 인스턴스**여야 한다(`concl ⊑ goal`).
대칭 거리로는 이 방향을 못 담으므로 잔차를 나눈다.

```
res  = size(concl) − size(⊓)      premise 쪽에서 설명 안 된 부분  (불일치)
gen  = size(goal)  − size(⊓)      goal 쪽에서 lemma 가 못 채운 부분 (일반성)
```

* **`res = 0` ⟺ `concl ⊑ goal`** ⟺ `apply` 가 구문적으로 맞는다
* `gen` 이 크다 = lemma 가 goal 을 별로 설명하지 못한다 = **너무 일반적이다**

#### 최종 형태 — 한 매개변수 족

```
D_λ(concl, goal) = res + λ · gen
                 = (size(concl) − size(⊓)) + λ·(size(goal) − size(⊓))
```

**양 끝점이 우리가 아는 두 경우다.**

| λ | 되는 것 | 실측 |
|---|---|---|
| **0** | 순수 적용가능성 — `res=0` 이면 전부 0점 | **⑮-0 에서 무너진 그 설정** (A 45.4% → 18.2%) |
| (0,1) | 적용 가능하면서 **구체적인** 것을 선호 | ← 목표 지점 |
| **1** | 대칭 격자 거리 `d` | 트리 완전일치만 0 (지금 `EQ_W` 가 잡는 경우) |

**이전 실패가 이 틀 안에서 설명된다 — λ=0 이었던 것이다.**
`forall A (x:A), P x` 같은 공허한 lemma 는 `res=0` 이라 만점을 받지만
`gen` 이 거대해서 λ>0 이면 자동으로 밀려난다.
그리고 **`D_λ = 0 ⟺ α-동치`** 가 모든 λ>0 에서 유지된다.

> 정규화가 필요하면 `D_λ / size(goal)` 또는 Steinhaus 변환
> `d / (size(t₁)+size(t₂)−size(⊓))` 로 [0,1] 에 넣는다(거리성 보존).

#### 확장 ① `rewrite` — 같은 연산자를 부분항에 양화

```
D_rw = min over (u ∈ 부분항(goal)), (s ∈ {LHS, RHS})   D_λ(s, u)
```

수식 하나로 통일된다. `rewrite` 가 lemma 사용의 **45.5%** 인데 지금은 결론 전체만 본다.

#### 확장 ② 남는 의무(obligation) 비용

`L : H₁ → H₂ → C` 를 쓰면 `H₁,H₂` 가 **새 goal** 이 된다. 그건 남는 일이다.

```
Cost = D_λ(C, goal) + μ · |hyps(L)|
```

거리가 아니라 **비용**이 되어 "지금 얼마나 맞나 + 뒤에 얼마나 남나"를 함께 잰다.

#### 구현 메모

* **α 자유**: 바인더를 de Bruijn 으로 정규화하면 α-동치가 **구문적 동일**이 되어
  lgg 가 그냥 맞아떨어진다. 별도 처리가 필요 없다.
* **복잡도**: 1차 반유니피케이션 `O(|t₁|·|t₂|)`, 부분항 양화까지 `O(|goal|·|t|)`.
  결론은 작아서 부담이 없다(현재 구조 판정이 스텝당 ~140ms).
* **기존 코드와의 차이**: `sig_anti_unify` 는 `공통노드수 / max크기` = `size(⊓)/max` 를 준다.
  이건 **유사도**이고 방향성도 일반성 벌점도 없다. 셋을 넣으면 위 정의가 된다.
  가중치도 `AU_W=0.01` vs `EQ_W=3.0` 으로 **반대로 걸려 있다.**

#### 잴 것

λ 를 0 → 1 로 훑으며 **A 와 C 를 따로** 기록한다. ⑮-0 의 실패가 정확히
"C 는 좋아지고 A 가 무너지는" 형태였으므로 합친 지표만 보면 못 잡는다.
`μ`(의무 비용)는 λ 를 고른 뒤 따로 훑는다.

---

### ⑮-A-old ★ (이전 서술) α-동치를 0 으로 두는 거리 함수

`d(goal, premise) = 0` 을 α-동치(변수 이름만 다른 같은 명제)에 두고,
구조가 벌어질수록 커지는 값을 정의한다.

```
d = 0        결론이 goal 과 α-동치           ← 지금 EQ_W 가 잡는 경우
d 작음        인자 하나가 다름 · 부분항만 일치
d 큼          머리 기호가 다름 · 추상화한 자리가 많음
```

**만드는 법 — 반유니피케이션(anti-unification)의 잔차**

goal 과 premise 결론의 **최소 일반화(LGG)** 를 구하면, 같아지기 위해 **추상화해야 했던
자리**가 나온다. 그 자리들을 두 종류로 가른다.

| 추상화한 자리 | 뜻 | 비용 |
|---|---|---|
| premise 쪽이 **바인더 변수** | 인스턴스화하면 되는 자리 | **0** — 정상 |
| premise 쪽이 **고정 기호**인데 다름 | 진짜 불일치 | **> 0** |

```
d = (고정 기호 불일치 노드 수 + λ · 추상화한 자리 수) / goal 크기
```

두 번째 항 `λ·(추상화 수)` 가 **"너무 일반적인 것"에 붙는 벌점**이다.
`forall A (x:A), P x` 는 맞기는 하지만 추상화가 많아 거리가 멀어진다 — ⑮-0 의 실패를 막는다.

**부품은 이미 있다.**

```python
sig_anti_unify(gs, ps)   # 공통 구조 노드수 / 큰 쪽 크기 · 등식 양변 · 부분항까지 본다
AU_W = 0.01              # ← 그런데 가중치가 0.01 (동점 처리용)
EQ_W = 3.0               # ← 이진 일치는 3.0
```

재료가 갖춰져 있고 **가중치만 반대로 걸려 있다.** 먼저 할 일은
`sig_anti_unify` 를 위 정의(잔차 + 일반성 벌점)로 다듬고 `AU_W` 를 올려 가며
**A 와 C 를 따로** 재는 것이다.

**★ 반드시 A 와 C 를 나눠서 잰다.** ⑮-0 의 실패가 정확히 "C 는 좋아지고 A 가 무너지는"
형태였다. 합친 목표지표만 보면 못 잡는다.

**되돌리기 쉽다** — `AU_W`/`EQ_W` 는 상수라 스위치 하나로 원복된다.

---

### ⑮-A2 매칭도 — 전부/전무를 **연속값**으로

트리 완전일치 대신 **단방향 유니피케이션**으로 "얼마나 맞는가"를 잰다.
(premise 의 바인더를 메타변수로 두고 goal 에 맞춰 본다.)

```
score = 맞아떨어진 노드 수 / goal 노드 수        (0.0 ~ 1.0)
완전일치는 1.0 이므로 지금 규칙을 **포함**한다.
```

`applicable.py` 에 항 파서와 단방향 유니피케이션이 **이미 있다**. 점수만 뽑으면 된다.

이러면 "인자 하나만 다른" 경우가 0점이 아니라 0.8점이 되고, `EQ_W` 같은 절벽이 사라진다.

### ⑮-B `rewrite` 전용 신호 — 등식 한쪽 대 부분항

결론이 `a = b`(또는 등록된 관계)인 premise 는 **`a` 를 goal 의 모든 부분항과** 맞춰 본다.

```
rewrite 점수 = max over (goal 의 부분항 t) 매칭도(t, L의 LHS)
```

`rewrite` 가 lemma 사용의 45.5% 인데 지금은 그 절반이 애초에 안 잡히는 질문을 받고 있다.
※ 대칭이므로 RHS 도 본다(`rewrite <-`).

### ⑮-C 정규형 색인 — 점수 말고 **조회**

premise 의 결론을 α-정규화 + 인자순서 정규화한 **정규형**을 키로 색인한다.

```
Lemma foo x y : x + y = y + x     →   정규형  "#0 + #1 = #1 + #0"
Lemma bar a b : a + b = b + a     →   같은 키
```

그러면 "같은 명제, 다른 변수명"이 **해시 조회 한 번**이다. 점수도 가중치도 없다.
**cut 경로가 랭킹이 아니라 사전 조회가 되므로 `EQ_W` 가 통째로 사라진다.**

우리는 이미 이름 정규화를 하고 있으니(normalize.md) 정규형을 만드는 부품이 대부분 있다.

### ⑮-D ★ 질의를 goal 이 아니라 **"필요한 명제"** 로 — 가장 예쁜 안

지금 cut 은 **데이터 준비 때만** 쓰인다. 추론에서도 같은 구조로 가면:

```
① 모델이 필요한 명제를 말한다        assert (forall n m, n + m = m + n) as H.
② 그 명제로 검색한다                 질의 = P  (goal 이 아니라)
③ 맞는 lemma 가 최상위로 온다        exact add_comm.
```

**질의가 곧 찾는 것의 명제**이므로 트리일치 특례가 필요 없다 — 자연히 1위가 된다.
C 가 93~95% 인 이유가 정확히 이것이고, 지금은 그 이득을 **학습 데이터에서만** 쓴다.

탐색이 하위 goal 을 따로 푸는 구조와도 맞고, ⑫(가)의 하위 goal 예제가 이걸 직접 가르친다.
→ **⑫(가) + ⑮-D 가 한 쌍이다.**

### ⑮-E 가중치를 손으로 정하지 말 것

`EQ_W = 3.0` 도 RRF 의 `k = 60` 도 근거 없이 정한 상수다.
gold 라벨(실제로 쓰인 premise)이 있으므로 **로지스틱 회귀 정도로 뽑을 수 있다.**

GBDT 는 이미 시도해 실패했는데(problem_of_gbdt.md), 원인은 **학습·추론 후보집합 불일치**였다.
가중치만 뽑는 선형 결합은 그 실패 모드가 없다 — 후보 생성은 그대로 두고 **결합 계수만** 바꾼다.

### 순서와 판정

| 안 | 무엇을 없애나 | 비용 | 위험 |
|---|---|---|---|
| **⑮-A 매칭도** | `EQ_W` 절벽 | 부품 있음 · 중간 | 낮음 |
| **⑮-B rewrite 신호** | rewrite 에 틀린 질문 | 중간 | 낮음 |
| ⑮-C 정규형 색인 | `EQ_W` 자체 | 큼 | 중간(정규형 정의) |
| **⑮-D 질의=명제** | 특례가 필요한 이유 | 추론 경로 변경 | 중간 |
| ⑮-E 가중치 학습 | 손튜닝 상수 | 작음 | 낮음 |

**⑮-A → ⑮-B 순으로 권한다.** 둘 다 지금 구조를 유지한 채 신호만 바꾸므로 되돌리기 쉽고,
효과는 A/B/C 지표로 바로 잰다.

⑮-C·⑮-D 는 구조 변경이라 ⑬(전이 갭)이 갖춰진 뒤에 판단한다 —
**"예뻐졌다"가 아니라 "전이가 좋아졌다"로 판정해야 한다.**

> 이 프로젝트에서 작은 표본만 보고 "된다"고 판단했다가 뒤집힌 적이 네 번 있다.
> 특히 ⑮-C·⑮-D 는 A(일반 goal)와 C(재검색)에서 **정반대 방향**으로 움직일 수 있다.
> 반드시 둘을 나눠서 재고, 목표지표 `A + (1-A)×C` 로 합쳐 본다.
