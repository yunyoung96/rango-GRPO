# 구조 기반 contrastive 재랭킹

`scripts/train_contrastive.py` (학습) · `src/tactic_gen/contrastive_rank.py` (추론)

> 지표 정의는 [README](README.md) 참조. 분모는 **gold lemma 를 쓰고 그 lemma 가 후보 풀에
> 실제로 있는 스텝**. R@k = 하나라도, ALL@k = 전부.

---

## 1. 초등학생용 설명

공식 카드를 찾을 때, 지금까지는 **글자가 얼마나 겹치나**를 셌다. 그런데 이름은 프로젝트마다
다르다 — 어떤 사람은 `add_comm`, 어떤 사람은 `plus_comm` 이라 부른다. 새 프로젝트에 가면
그 이름들을 처음 보므로 아무 도움이 안 된다.

그래서 **이름을 전부 지운다.** 대신 "무엇과 무엇이 같은 자리에 있나"만 남긴다.

```
문제:  le (succ zero) a      →   ( S0 ( S1 G ) V )
카드:  le (succ n) m         →   ( S0 ( S1 M ) M )
                                   ↑    ↑
                            둘 다 같은 함수가 같은 자리에 있다 = S0, S1
```

`S0`, `S1` 은 **둘 다에 나오는 것**, `G` 는 문제에만, `M` 은 카드에만, `V` 는 지역 변수다.
이렇게 바꾸면 남는 글자는 **57가지뿐**이고, 그 안에 프로젝트 고유 이름이 하나도 없다.

그 다음 신경망에게 "이 모양 쌍이 잘 맞물리나?"를 배우게 한다. 이름을 안 배웠으니
**처음 보는 프로젝트에도 그대로 쓸 수 있다** — 이것이 이 방법의 핵심 주장이다.

---

## 2. 왜 이 표현인가 — 전이(transfer)

| 신호 | 새 프로젝트에서 | v8 익명화 프롬프트에서 |
|---|---|---|
| lemma 이름 subword | ✗ 작명 관례가 달라 안 통함 | ✗ 이름이 `L#` 로 바뀌어 볼 수 없음 |
| tfidf 토큰 | △ 전역 상수는 통하고 지역 이름은 안 통함 | △ |
| **정렬 익명 구조** | **✓ 어휘에 고유 이름이 없음** | **✓ 애초에 이름을 안 씀** |

`structural_repr.pair_tokens` 가 goal·premise **쌍**을 받아 닫힌 어휘 57개로 익명화한다.
공유 상수만 같은 슬롯(`S0..S9`)을 받고, goal 전용은 `G`, premise 전용은 `P`, 지역 변수는
`V`, 메타변수는 `M` 이다.

---

## 3. 왜 cross-encoder 인가 (그리고 그 대가)

정렬 익명화는 **쌍에 의존**한다 — 무엇이 공유되는지 알아야 `S0` 을 줄 수 있다. 그래서
goal 과 premise 를 따로 인코딩할 수 없다(bi-encoder 불가). 후보마다 한 번씩 모델을
돌려야 한다.

대가는 비용이다. 풀이 1만 개인데 전부 돌릴 수는 없다 → **3단계 구조**로 쓴다.

    ① tfidf 로 상위 2000            (싸다)
    ② RRF(tfidf, C') 로 정렬        (중간)
    ③ 상위 200 만 cross-encoder 로 재정렬   (비싸다)

---

## 4. 모델과 학습

```
표현    pair_tokens → 토큰 id (어휘 57, 최대 길이 192)
모델    작은 Transformer — d=256, 6층, 8헤드, norm_first, 평균풀링 → 점수 1개
손실    InfoNCE — 사례마다 gold 1개 + tfidf 상위 hard negative 24개를 한 묶음으로
        gold 점수가 가장 높도록 softmax cross-entropy
데이터  data/cpairs_train.jsonl (134MB) · cpairs_val.jsonl (14MB)
산출    data/contrastive_ce.pt (19MB, 13 epoch)
```

어휘가 57개뿐이라 모델이 작아도 된다.

## 5. 결과

### 5-1. 학습 당시 (tfidf 와만 비교)

```
epoch 13: loss 2.8901 · 재랭킹 top1 7.0% top5 21.6% top10 36.9%
                        (tfidf 원본      3.1%      11.2%      17.0%)
최고 val top5 = 27.9%
```

top10 이 17.0% → 36.9% 로 **두 배**다. 여기까지만 보면 성공으로 보인다.

### 5-2. ★ 그러나 RRF 와 비교하면 이득이 없다

**분모: gold 가 후보 풀에 있는 TEST 스텝 40건 (예비 — 표본이 작다)**

| 랭커 | 목표지표 R@50 | 목표지표 ALL@50 |
|---|---|---|
| rrf | **96.1%** | **95.0%** |
| eq | **96.1%** | **95.0%** |
| ctr (RRF 융합) | 95.4% | 91.8% |

`ctr` 은 RRF 에 얹어도 **아무것도 더하지 못한다**. tfidf 를 이긴 것은 맞지만, tfidf 는
이미 RRF 에 크게 뒤지는 기준선이었다.

> ★ 교훈: 약한 기준선(tfidf)만 이기고 "성공" 이라고 부르면 안 된다. 이 프로젝트에서
> 세 번째로 같은 실수를 할 뻔했다(학습 랭커 §10.3, Coq `Fail` 필터 §10.4, 계층 랭커 §16).

### 5-3. 결합 방식이 결과를 뒤집는다

처음에는 CE 점수로 상위 200 을 **통째로 덮어썼다**. 그러면 RRF 신호가 사라진다.

| 결합 방식 | 목표지표 ALL@50 |
|---|---|
| CE 로 덮어쓰기 | **65.2%** |
| RRF 융합 `rrf + 1/(60+CE순위)` | **91.8%** |

재랭커가 기준선보다 약할 때, **덮어쓰기는 재앙이고 융합은 안전하다.**

## 6. 왜 안 되나 — 진단

| 의심 | 근거 |
|---|---|
| **손실이 정체** | 12~13 epoch 내내 2.89~2.90. 학습이 더 안 나아갔다 |
| **정보가 이미 C' 에 있다** | RRF 의 C'(결론 head IDF 코사인)도 구조 신호다. 익명 구조 n-gram(F)·anti-unification(G) 도 RRF 에 넣으면 개선 0 이었다 — **구조 정보끼리 중복**된다 |
| **표현이 너무 거칠다** | 57토큰 익명화는 인자 위치를 보존하지만 **깊은 중첩을 max_len 192 에서 자른다** |
| **hard negative 가 tfidf 상위** | tfidf 가 약하므로 negative 도 쉬웠을 수 있다 |

## 7. 다음에 시도할 것

1. **negative 를 RRF 상위로** 교체 — 지금 기준선이 RRF 이므로 negative 도 거기서 와야 한다
2. **손실 정체 해소** — 학습률 스케줄, 층/차원 확대, epoch 확대
3. **`eq` 신호를 특징으로 주입** — 트리 완전일치를 모델이 직접 보게 한다
4. **TEST 전이를 큰 표본으로** 재측정 — 지금 40건은 결론을 내기에 부족하다

지금 상태로는 **RRF/eq 를 대체하지 못한다.** 위 넷을 해보고도 안 되면 접는다.
