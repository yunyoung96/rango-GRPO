## 1. 고친 문제

### 1-1 ★ 추론 프롬프트가 학습과 어긋났다 — 2.2% → 0%

**증상.** 같은 예제인데 프롬프트가 다르다.

```
학습   Theorem _G0 l : list_injective l -> P l.
추론   Theorem fin_reif l : list_injective l -> P l.
```

모델은 `_G0` 기준으로 학습되므로, 추론에서 실명을 보면 그만큼 OOD 다.

**분모/분자.** TRAIN 400 예제 중 매핑이 생긴 371 예제가 분모.
그중 **8건**이 불일치 = **2.2%**. 8건이 **전부 `_G0`**(증명 중인 정리 이름) 였다.

**원인 ① — `_ndecl` 검사가 프롬프트가 아닌 넓힌 `avoid_text` 를 보고 있었다.**

`_ndecl > 1` 은 "**프롬프트에** 같은 이름 선언이 둘 이상인가" 를 묻는 검사다.
동명 lemma 셋이 전부 `_G0` 이 되어 구분 불가해지는 것을 막는 방어다.

그런데 추론의 `avoid_text` 는 **이름 할당 충돌**을 피하려고 프롬프트 너머까지
넓혀 두었다 — premise 전량 · 유사 증명 · `proof_script`. (실명 `T1` 이
`Reducef` 로 뒤바뀐 사고를 막으려고 넓힌 것이다.)

넓힌 텍스트로 선언을 세니 **같은 선언이 중복 집계**되어 `_ndecl ≥ 2` 가 되고,
정리가 매핑에서 빠져 `LAST_THM_DECL` 로만 넘어왔다. 그런데 프롬프트에는 그
정리의 **선언부가 아예 없으므로** 폴백인 `substitute_theorem_decl` 도 못 바꾼다.

실측 추적 (4건 전부 동일한 형태):

```
학습  build_mapping → N개,   LAST_THM_DECL=None       → _G0 로 치환됨
추론  build_mapping → N−1개, LAST_THM_DECL='fin_reif' → substitute … '★안바뀜'
```

→ `build_mapping` 에 **`decl_text` 인자를 새로** 두어 두 목적을 분리했다.
기본값이 `avoid_text` 라 **학습 경로 동작은 그대로**다.

**원인 ② — 매핑이 비면 조기 반환해 선언부 익명화를 건너뛰었다.**

```python
if not m:
    return text          # ← 바로 뒤의 LAST_THM_DECL 처리를 통째로 건너뛴다
```

학습(`collate`)은 매핑이 비어도 그 처리를 **무조건** 한다.
실측: 학습 `bm=1개/LAST=None` → `Lemma _G0 n p :` /
추론 `bm=0개/LAST='ltb_lt'` → 조기 반환 → `Lemma ltb_lt n p :`.

**검증.**

| 검사 | 수정 전 | 수정 후 |
|---|---|---|
| 잔여 불일치 탐색(TRAIN) | 4/265 | **0/500** |
| 전체 검증 D 항목 | 8/371 = 2.2% | **0/392 = 0%** |
| 매핑 적용 예제 | 371/400 | **392/400** |

매핑 적용이 371→392 로 는 것은, 정리 이름이 이제 정상적으로 매핑에 들어가기 때문.

### 1-2 `room` 이 정답 자리를 128 만 예약하고 있었다

주입 예산 계산이 별도 변수 `AUG_OUT_TOKENS`(하드코딩 기본 **128**)를 보는데,
collator 의 `out_tokens` 는 어제 **256** 으로 올렸다. 예전엔 둘 다 128 이라
우연히 맞아 있었다.

```python
room = hard - _ntok(base_str) - out_tokens - margin   # out_tokens 가 128
```

최악의 경우 `base + room + 256 = 3072 − 128 − 16 + 256 = 3184` 로 **112 토큰 초과** →
`truncation_side="left"` 라 `[PREMISES]` 앞쪽이 다시 잘린다. 어제 내가 만든 회귀다.
→ `_D.num("OUT_TOKENS")` 로 통일.

### 1-3 분석 스크립트 27개가 `HARD_SEQ_LEN=2048` 을 하드코딩

프로덕션 기본값이 3072 로 올랐는데 스크립트들은 2048 로 재고 있었다.
**앞으로 이 스크립트로 측정하면 조용히 틀린 수치가 나온다.**
전부 `_D.num("HARD_SEQ_LEN")` 로 이관. `rerank_ablation.py` 의
`os.environ["HARD_SEQ_LEN"]` 직접 첨자(KeyError 위험)도 함께 수정.
